# Refresh qiven-math CI Foundation checkout pin

This is dependency-baseline hygiene, not a discovered Batch 008 algorithm defect. Batch 008 received two complementary forms of evidence: local Windows Debug/Release validation against current Foundation, and full cross-platform validation of the exact merged Math tree against the workflow's historical Foundation pin. Because the intervening Foundation sequence reconciled Devkit-managed files and added ownership metadata rather than changing the public Foundation source API consumed by Math, the stale workflow pin does not block Batch 008 closeout.

It does matter for future evidence. When the Math CI workflow or its dependency pins are next touched, update the Foundation checkout ref deliberately and run the required CI plan against the selected baseline. Do not silently follow moving `main` unless the repository explicitly adopts that policy; an explicit immutable SHA remains preferable when reproducibility is required.

# Reassess qiven-context retrieval reliability before resuming Operator merge

This is not a request to make a vector database canonical and not a predetermined choice of database product. It is a reliability gate on the retrieval subsystem.

The first step is to freeze a benchmark and acceptance contract before choosing/tuning the retrieval implementation. The benchmark must include at least:

- the Windows Python resolver lesson phrased without copying its memory title/tags;
- historical decisions described through semantically equivalent but lexically distant wording;
- meaningful task transitions inside a long-running conversation;
- negative controls where unrelated memories must not flood the working context;
- cross-domain distractors;
- tests proving retrieval actually runs rather than depending on the model remembering to invoke it.

Then compare the current deterministic/metadata baseline with at least one semantic retrieval candidate and a hybrid/fused path. Record recall, retrieval noise, provenance quality, latency, rebuildability, and operational complexity. Define critical acceptance thresholds before observing final benchmark results.

Operator Phase 1 remains valuable work, but merging/releasing it while the cognition substrate is under reassessment would continue construction on an epistemically uncertain foundation.

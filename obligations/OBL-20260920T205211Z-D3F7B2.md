# Land the common result/status vocabulary in Foundation at its defined trigger (first recoverable-failure API or Runtime K1 work)

The 2026-09-20 distillation review established that the draft's result
shapes are Foundation candidates with a defined trigger rather than
speculative work. This obligation keeps the trigger visible at retrieval
boundaries: when the Runtime program's typed-evidence work (RCA-3/RCA-4)
or any Foundation API first needs a recoverable failure channel, the
vocabulary lands in qiven-foundation first and consumers depend on it —
never the reverse (philosophy sections 1/7; pit P-49 preflight rule).

## Completion (2026-09-21)

Completed ahead of the RCA-3/RCA-4 consumer horizon: the trigger fired
with the Runtime program start itself (RCA-0 named Result as a day-one
foundation contribution). Completion evidence:

- qiven-foundation PR #9 (merge `38f0eb2`): `qiven::Result<T, Reason>`
  landed as a tested public contract (23/23 tests Debug + Release; CI run
  `35586311558` full cross-platform matrix SUCCESS at `d0c0130`).
- qiven-runtime PR #6 (merge `146659f`, RCA-1): `ProfileBuilder::build()`
  returns `qiven::Result<DeploymentProfile>` — first runtime consumption,
  no local result shape introduced anywhere in qiven-runtime.
- Both exact heads passed their repository gates (local PASS receipts in
  the PR records).

# Design qiven-context.exe as a semantic Context Engine with representation-independent storage

Completed by revised ADR-0033 after explicit user authorization to revise,
publish and merge. This closes architecture definition only, not implementation,
storage selection or authority cutover. K1 is the next implementation boundary.

The architecture review begins from semantic ownership rather than a database product. `qiven-context.exe` is one provider entry and potentially one local service/consumer interface; it is not the definition of Context itself.

The current GitHub repository remains canonical until a separately accepted authority migration proves import/export semantic equivalence, backup/restore, provenance, continuity, and governance behavior. A database becoming operational is not by itself an authority cutover.

Provider and consumer are roles rather than biological/AI identity classes: Jason, ChatGPT, CI, runtime systems, and future agents may each provide observations/evidence or consume compiled Context under different authority rules.

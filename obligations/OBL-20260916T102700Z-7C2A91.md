# Reconcile and remove Qiven-v6 unmanaged temporary repository clones

Known names/patterns created or requested during Qiven-v6 include:

- `%TEMP%\\qiven-context-v2-acceptance`;
- `%TEMP%\\qiven-context-v2-final-37fdbb33`;
- `%TEMP%\\qiven-context-v2-canonical-merge`;
- `%TEMP%\\qiven-context-guardrail-acceptance`;
- `%TEMP%\\qiven-context-branch-gc-*` (the PowerShell GC path was designed to self-remove if it completed, so verify before assuming it remains);
- a possible literal directory named `%QV2%` produced by the earlier same-line CMD expansion mistake; its parent location is not established from durable evidence and must be discovered rather than guessed.

Deletion must be identity-safe: verify a candidate directory is the intended Qiven temporary repository/materialization before removing it. Do not broad-delete unrelated user temporary data by name pattern alone.

After reconciliation, Operator-owned scratch/worktree lifecycle is the accepted isolated-materialization mechanism. Ambient `%TEMP%` repo cloning is not the normal validation path.

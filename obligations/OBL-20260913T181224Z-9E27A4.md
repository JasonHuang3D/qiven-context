# Design one common result/status abstraction before Foundation APIs need structured recoverable status

This is intentionally deferred, not forgotten. Current APIs use contracts appropriate to their semantics (`nullptr`, `std::optional`, booleans, assertions for programmer preconditions, and explicit checked helpers). A generic status/result type should enter Foundation only when a concrete public API requires it and the shared semantics can be designed from evidence rather than anticipation.

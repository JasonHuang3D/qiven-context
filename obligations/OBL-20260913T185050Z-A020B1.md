# Make the old-Python resolver test fail specifically on version rather than interpreter validity

The current fixture passes `valid=False` while also labeling the mock as version `3.10.9`. Because the mock exits before reporting a usable interpreter/version, the test proves explicit-override failure and no fallback, but not the narrower fact that a runnable old interpreter is rejected specifically for its version.

This gap is deliberately non-blocking and should be fixed opportunistically when the resolver tests are already being modified.

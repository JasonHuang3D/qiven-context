# Resume Math Batch 008 vector algorithms after qiven-context cold-boot acceptance

Preserved candidate scope from the pre-pause discussion:

- `dot` for vectors;
- `cross` for `Vec3`;
- `length_squared`;
- robust `length`;
- `normalize` with a finite, non-zero programmer precondition;
- checked `try_normalize` returning false for zero/non-finite input and leaving the output unchanged on failure;
- `distance`;
- explicit-tolerance `is_near`.

The preferred robust normalization strategy is max-component scaling before length evaluation to avoid avoidable overflow/underflow. The initial near-comparison candidate is componentwise absolute tolerance, with no global epsilon and no implicit relative tolerance. Pure algebraic operations should remain `constexpr` where C++20 permits; square-root-dependent operations need not be forced into fake constexpr semantics. Fast-math is not part of the contract.

These details are preserved reasoning residue, not permission to skip normal Batch 008 CTO contract review. Re-confirm exact names and edge-case semantics before implementation.

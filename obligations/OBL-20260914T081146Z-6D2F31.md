# Improve human-facing Devkit adoption plan output

The existing adoption checker is operationally correct: it classifies all managed paths into `EXACT`, `MISSING`, and `CONFLICT`, refuses unsafe application, and states whether check mode changed the target. The remaining gap is presentation quality for a human operator.

When the adoption CLI is next touched, treat its output as an engineering interface rather than incidental logging. Prefer a compact hierarchy that makes mode, target, totals, category counts, conflicts, and final safety/result state obvious at a glance. Preserve deterministic plain text for CI/redirection; color may be layered on only when terminal capability is reliable and a no-color path remains available.

This is intentionally non-blocking for the already conflict-free Foundation adoption because changing Devkit presentation immediately would introduce another validation/merge cycle without improving the semantics or safety decision that was just verified.

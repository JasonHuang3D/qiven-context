# Separate architecture and release authority from local implementation execution

> **Superseded by ADR-0044 (2026-09-22).** The revisit condition this ADR
> itself named - one agent with verifiable local execution, remote
> repository control, approval boundaries and auditability - was met by
> supervised local-agent sessions. Publication/release authority
> separation survives through ADR-0036 typed handoffs (owner H2), not
> through agent-role staging. Role names remain as attribution and
> qualification labels.

## Context
Qiven needs high implementation throughput without allowing the local execution agent to silently expand architecture, rewrite release policy, or publish unreviewed work. The collaboration model also evolved after direct GitHub connector access became available to jason-brother.

## Decision
`jason-brother` is the CTO/architect/reviewer and owns architectural decisions, feature planning, remote review, CI selection, and merge/release gating. `jason-worker` is the local execution agent for authorized implementation, local builds/tests, and machine-local workflows. Worker branches use `jason-worker/*`; CTO/chat-driven remote-native work uses `jason-brother/*`.

By default jason-worker does not push, merge, open PRs, rewrite remote history, or change Git identity. The user remains the final operator and performs final merge by default. When GitHub connector access is available, jason-brother may directly implement authorized remote-native repository work; that capability does not imply access to the user's local Windows execution environment.

## Alternatives Considered
Giving the implementation worker end-to-end architecture, publication, and release authority; using one undifferentiated agent role for both local execution and CTO/review work.

## Consequences
Authority boundaries remain reviewable and local execution can proceed aggressively inside approved scope. Some work crosses a deliberate handoff boundary between local execution and remote review. Remote-native work can bypass unnecessary worker/user-push hops without weakening local-machine boundaries.

## Revisit Conditions
Revisit if a future execution environment provides verifiable local-machine execution, remote repository control, approval boundaries, and auditability in one agent without weakening separation of duties.

## Provenance
Genesis reconstruction from the committed Foundation agent contract and worker protocol, reconciled with the current qiven-context operating contract after GitHub App access enabled direct remote-native jason-brother work. Exact historical adoption time is not reconstructed here.

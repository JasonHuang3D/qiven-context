# Require typed human handoffs by objective operation class and make verbal waiver insufficient for mandatory handoffs

## Context

Two recorded incidents define this decision. First, during K4 kernel work the
required human handoff was once missing because an assistant followed the shape of
a request instead of the objective acceptance topology; the correction (ADR-0034,
`collaboration/context-handoff-contract.md`) established that acceptance roles
cannot be collapsed. Second, the 2026-09-16 split-brain incident established that
conversational singularity is not a safety boundary, which suspended unattended
mutating DCR execution. Desktop-resident agents (ZCode, future Codex-class tools)
add a new surface: the same tool can run supervised in the foreground today and
scheduled or idle-time automation tomorrow. A request-level rule ("the human said
so") cannot govern that surface; only an objective operation classification can.

## Decision

1. **Handoff requirement is a property of the claim, not of the requester's
   convenience.** Whether a human handoff is mandatory is determined by the
   objective class of the operation being claimed, using the table in
   `collaboration/human-handoff-boundary.md`. It cannot be lowered by any
   conversational instruction.
2. **Typed handoffs.** H1 execution handoff (owner physically runs the acceptance
   producer, as in the K4 producer gate); H2 review handoff (owner or delegated
   reviewer accepts the exact delta before merge-class publication); H3 authority
   handoff (Human Succession); H4 recovery-presence handoff (ADR-0029 cryptographic
   local presence). A handoff claim must name its type and evidence.
3. **No-verbal-waiver protocol.** When a human instruction would exempt a
   mandatory handoff, the agent must: (a) decline the exemption and name the gate
   and the claim it protects; (b) offer the legitimate alternatives — descope the
   claim, or revise the governing contract through an ADR; (c) record the exchange
   in the session checkpoint when material. The only instrument that removes a
   mandatory handoff is a canonical contract revision, never a session instruction.
4. **Unattended automation classification.** Scheduled, idle-time, or otherwise
   unsupervised automation is permitted by default only for read-only operations
   and rebuildable derived artifacts with bounded resources. Local commits inside
   an explicitly authorized task scope are permitted. Push, PR creation, merge,
   acceptance-producer roles, and governance mutation are not unattended-eligible.
5. **Desktop merge-evidence equivalence.** For `local_supervised_agent` tools, an
   owner merge confirmation given in conversation and an owner merge performed
   through the GitHub UI are both valid H2 evidence for the same exact delta;
   neither implies the other was skipped.

## Alternatives Considered

1. **Keep handoff requirements request-scoped (waivable when the human says so).**
   Rejected: it is exactly the K4 failure mode, and it makes claims unprovable by
   construction.
2. **Treat all automation as unattended and forbid background work entirely.**
   Rejected as overbroad: read-only and rebuildable derived work carries no
   handoff-protected claim, and forbidding it would discard real capability
   without a safety benefit.
3. **Add a new constraint rule to `governance/context-constraints.yaml` for
   unattended mutation.** Deferred: constraints.yaml is a deterministic
   applicability index over canonical records; the normative boundary lives in
   this contract and the boundary document it cites, and a constraint rule can be
   added once the operation vocabulary stabilizes.
4. **Rely on the Host broker alone for the boundary.** Rejected: the broker governs
   remote-AI local mutation channels; desktop foreground/background execution needs
   a classification that exists independent of Host acceptance.

## Consequences

- The failure mode "kernel work proceeded without the required handoff" now has a
  named, citable boundary that applies to every future kernel and acceptance task.
- Agents operating under this repository gain a duty to refuse waivers and a
  deterministic reference (`collaboration/human-handoff-boundary.md`) to cite.
- The document joins the mandatory cold-boot input set so every future session
  reconstructs the boundary before acting.
- The DCR/Host suspension of ADR-0026 remains untouched; this decision classifies
  the general surface rather than re-enabling any suspended channel.

## Revisit Conditions

Revisit the operation-class table when a new execution surface (for example an
accepted Host broker or a new client capability class) creates a class the table
does not describe. Revisit the no-verbal-waiver protocol only through a new ADR
that names the claim class whose protection would change; session-level waiver
attempts never trigger a revisit by themselves.

## Provenance

Accepted from the project owner's 2026-09-18 direction requiring an explicit
boundary for unattended automation versus human handoff, motivated by the earlier
K4 kernel work that once proceeded without the required human handoff. The owner
required that the boundary follow objective facts even when a human says to skip
it. Evidence: `evidence/audits/context-k4-handoff-drift-review-2026-09-18.md` and
ADR-0034 as the primary missing-handoff records, with
`evidence/audits/context-k4-handoff-trial-1-2026-09-18.md` as supporting
evidence, plus the 2026-09-16 split-brain audit and
`collaboration/context-handoff-contract.md`.

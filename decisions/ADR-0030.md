# Make qiven-context a participant-independent project continuity system

## Context

The original qiven-context architecture successfully externalized cognition from one LLM session, but its physical operating model accumulated too many manually maintained write surfaces. Session records stopped being maintained, the manual cognition ledger stopped while canonical records continued, placeholder evidence buckets never became operational, handoffs leaked into normative collaboration documents, and stale repository snapshots could appear beside live-authority claims.

The project owner clarified the stronger requirement: the project itself must remain continuable across session incidents, LLM/model/provider replacement, agent replacement, and eventually authorized human-operator changes. Known ADR/obligation/other conflicts must be cleaned rather than left as permanent competing context.

## Decision

qiven-context is Qiven's participant-independent project continuity system.

Canonical cognition must not depend on any one session, assistant identity, model-native memory, provider, local clone, or human recollection. Session checkpoints are bounded continuity evidence only; no cognition required for future project operation may exist solely in a session file.

The active write model is reduced to decisions, memory, obligations, projects, compact state, session checkpoints, governance, and curated audits. The v1 manual ledger is frozen as historical data rather than backfilled or dual-written. Placeholder CI/handoff/research evidence buckets are deprecated; irreplaceable snapshots belong in audits while live external evidence is cited by identity.

Conflict is a transient epistemic state. A newly discovered contradiction is surfaced first, then explicitly reconciled when evidence permits. Reconciliation establishes one active canonical interpretation for its scope/time, marks displaced records with lifecycle state, preserves provenance/history, and removes displaced cognition from default current retrieval. Genuine uncertainty remains explicit as an open question, blocker, risk, or obligation.

Context is updated through material transactions, not every conversational turn. Each transaction verifies evidence, classifies cognition, reconciles lifecycle, updates only affected canonical surfaces, updates compact current state and this session's checkpoint, validates invariants, and lands as one coherent Git commit.

The highest acceptance contract is Project Continuity: a fresh capable LLM and fresh authorized human with no prior conversation/model memory must reconstruct the project, authority, accepted state, candidates, blockers, relevant negative knowledge, live-verification needs, and next valid action from canonical remote context plus live project evidence.

## Alternatives Considered

Continue the v1 L0-L4 physical multi-write model unchanged; backfill missing ledger/session history; make session handoffs the primary continuity contract; keep all conflicting records active and rely on future LLM reasoning to choose among them.

## Consequences

The conceptual distinction between evidence, canonical interpretation, and derived retrieval remains, but it no longer requires a manually duplicated event stream. Active cognition becomes smaller and more deterministic. Historical material remains auditable through record lifecycle and Git history.

Validators must enforce operating invariants in addition to JSON/YAML schema shape. Future Context design is judged by continuity under participant replacement rather than by how much history it stores.

## Revisit Conditions

Revisit the physical store when measured continuity/retrieval evidence shows the current source model cannot scale, when multi-writer organizational governance becomes real, or when another canonical mechanism can provide stronger continuity without sacrificing inspectability/provenance.

## Provenance

Accepted by the project owner during the Qiven-v6 Context v2 review after a repository-wide operating-model audit.

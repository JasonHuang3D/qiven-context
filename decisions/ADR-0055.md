# Simulated ZCode hook lifecycle gate as the interim MVP-4 exit

## Context

Four owner-live MVP-4 H1 trials failed on infrastructure defects each
invisible to the prior validation layer (trial 1 assumed payload
field; trial 2 borrowed-payload lifetime; trial 3 one-frame host +
admission mismatch; trial 4 the hello/event deadline split), and the
2026-09-25 harness PoC contaminated the owner's official installation
and browser. On 2026-09-26 the owner retired the owner-live GUI trial
as the interim acceptance instrument and directed MVP-4 toward tests
that simulate the real ZCode invocation sequence. qiven-docs PR #4
deliberated the replacement across multiple cross-LLM rounds; the
owner accepted PR #4 (`3529cd6`/`52a8a32`, documents under
qiven-docs `accepted/2026-09-26/`). This ADR lands the accepted
proposal's normative content canonically and amends the real-H1
wording of ADR-0047 decision 6 and ADR-0050 decision 8 (their dated
amendment sections point here).

## Decision

1. **The interim MVP-4 exit gate is the simulated ZCode hook
   lifecycle gate.** The test launches the candidate production hook
   executable as an external process with the exact stdin JSON and
   environment form it is supposed to receive, and runs the candidate
   RuntimeHost behind the actual named pipe and packaged
   profile/configuration. The simulator replaces only the caller and
   external inputs - the test must model the actual hook lifecycle,
   never call a host handler directly and label it ZCode integration.
2. **Independently sourced fixtures and oracle.** Fixtures derive from
   a pinned official ZCode hooks implementation
   (`zai-org/ZCode@29628c9`), published hook payload contracts, and
   the historical H1 captures; each fixture's revision and provenance
   is recorded. The oracle is an independently specified expected
   verdict (accepted contract or recorded incident), never the
   current implementation's output copied into the fixture. Source
   parity with the installed Desktop build is a documented assumption,
   not a test oracle; a mismatch is labeled, not assumed away.
3. **Required lifecycle coverage.** At minimum: (a) SessionStart -
   hello AND `session_start` event on the real connection, one
   registered session, journal row, correlated identity and typed
   verdict, idempotent repeat; (b) PreToolUse - governed mutation
   denies in the specified class without executing an effect;
   `not_governed` only under its real preconditions; without
   registration, unknown tool, missing admission/configuration,
   expired cognition or mismatched manifest, the action fails in its
   specified class ("any verdict" is not a pass); (c) PostToolUse and
   lifecycle closure - correct correlation, shutdown/restart/
   duplicate-ID/new-session isolation contracts; (d) packaging and
   path forms - the shipped kit resolves its profile from its own
   root; Windows alias/reparse/relative/Unicode fixtures give their
   expected conservative result (a CWD profile cannot substitute for a
   missing kit profile; lexical prefix alone cannot claim filesystem
   authorization).
4. **The five incidents are distinct discriminating cases.** Trial 1
   absent field, trial 2 borrowed-payload lifetime, trial 3 hello/event
   + admission mismatch, trial 4 total deadline, and the separate
   kit-preflight incident each appear as distinct old-fail/new-pass
   cases (failing on the historical defective revision or an explicit
   fault injection for the same reason, passing on the candidate),
   each with a plausible wrong fix the test rejects. A full
   hello/event transaction must close within one monotonic hook
   timeout - a one-frame or per-frame-only timer cannot close trial 4.
   The owner's 100-experiment breadth target stands as a target;
   invariant and discriminating-case coverage decides whether the
   count is meaningful, a count alone is never a verdict, and the
   owner may amend the numeric floor explicitly.
5. **Skip semantics are acceptance-fatal.** A skipped host/hook/
   scenario is NOT_RUN / failure for acceptance, never a green
   receipt; the qiven-runtime kit test `h1_kit_test.py`'s skip-success
   semantics are fixed in the gate build (its packaging checks remain
   useful). The publication gate rejects absent, skipped, stale or
   failed receipts.
6. **Typed claim boundary.** An exact-head simulated pass is reported
   `MVP4_SIMULATION_ACCEPTED` - never as execution proof of the
   installed Windows Desktop carrier, whose scope stays labeled
   `INSTALLED_DESKTOP_EXECUTION_UNVERIFIED`. Report separate states
   for `SIMULATED_HOOK_HOST_PASS`, `PINNED_SOURCE_CONTRACT_REVIEWED`,
   and `INSTALLED_DESKTOP_EXECUTION_UNVERIFIED`; an absent required
   fixture, skipped platform leg, changed source/profile digest or
   missing registered-session negative control makes the simulation
   state NOT_VALIDATED.
7. **Receipt binding.** The fixture catalogue, expected outcomes,
   candidate Runtime/Hook/Foundation/Devkit source graph, profile
   digest, platform/toolchain and actual test command bind to a
   receipt at the exact candidate head; the suite runs on the same
   candidate before any MVP-4 acceptance claim and again whenever the
   relevant hook/IPC/profile inputs change. A gate that merely exists
   in the repository, or runs on an older locked graph, is not proof.
8. **Complete-mediation honesty is unchanged.** The hard claim still
   holds only for the mediated tuple (ADR-0047 decision 6); the
   writable-child/subagent bypass is a required negative coverage
   case - if an uncovered delegation/tool path can write inside the
   governed root, the complete-mediation claim is blocked even when
   the simulated main session passes. A read-only child is not proof
   of mediation.
9. **Real-harness ban.** No real ZCode harness build, launch,
   redirect or mutation on the owner machine (the 2026-09-25 PoC
   contamination class). A later real-carrier trial requires separate
   authority and a genuinely disposable environment. This ADR creates
   no ZCode CLI transplant requirement and no Foundation
   wholesale-adoption prerequisite; the simulated gate is not
   conditioned on new Foundation code.
10. **Sequencing.** Substantive MVP-5 stays frozen until CA-2 AND the
    simulated-gate MVP-4 exit; the MVP-4 corrective lane and MVP-5/CA
    transitions follow ADR-0050 as amended. Lower-layer code defects
    the simulated tests detect are separately admitted at their
    semantic owners with old-fail/new-pass evidence - they are not
    prerequisites of this gate. The compaction-recurrence hypothesis
    remains a standing TESTABLE hypothesis, not a proven cause; the
    interim gate blocks publication of an unproven candidate but
    cannot promise every intermediate model decision used all
    intended context.

## Alternatives Considered

Continuing owner-live GUI H1 trials (rejected: four trials failed on
mutually distinct infrastructure defects each invisible to the prior
layer, and the trial loop consumes owner hands per attempt); counting
the existing kit test as H1 proof (rejected: it skips when the host
executable is absent and still returns success); a real-ZCode-CLI
mock-LLM rig on the owner machine (rejected: real-harness execution
class, banned); conditioning the gate on Foundation typed primitives
or a ZCode transplant (rejected 2026-09-26 owner reflection:
intent/status drift; defects stay as evidence and discriminating test
cases, fixes are separately admitted at semantic owners).

## Consequences

MVP-4 acceptance becomes deterministic, repeatable and machine-checked
at every publication boundary, with an honest typed residual for the
installed Desktop carrier. The hello-deadline fix and preflight
`session_start` coverage fold into the gate-build wave per
`OBL-20260926T234500Z-B4C5D6`. WR-5/WR-6 remain unblocked but
sequence after the wave; MVP-5 stays frozen per ADR-0050 as amended.

## Revisit Conditions

A separately authorized disposable-environment real-carrier trial; a
Qiven-owned request-boundary activation mechanism that supersedes
publication-time receipts (the compaction continuity program); the
owner amending the numeric breadth floor explicitly.

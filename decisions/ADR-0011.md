# Separate Devkit-managed shared conventions from bootstrap-only repository-owned files

## Context
Not every file produced during repository bootstrap should remain centrally controlled. Shared engineering conventions need a synchronization path, while domain-facing repository files are expected to diverge legitimately.

## Decision
Devkit classifies template output into two ownership classes. Managed files are shared conventions that may later be synchronized by Devkit. Bootstrap-only files are starting points that become repository-owned and are never overwritten by sync.

At template version 0.1.1 the managed set contains formatting/editor policy, presets, AGENTS.md, engineering protocol, and local developer tools. The bootstrap-only set is `.gitignore`, `README.md`, `CMakeLists.txt`, and `.github/workflows/ci.yml`.

## Alternatives Considered
Treating the entire generated repository as Devkit-owned; treating every generated file as repository-owned with no later synchronization path; using path-by-path ad hoc ownership rules during each update.

## Consequences
Shared engineering conventions can evolve without taking ownership of product architecture or repository-specific build/CI choices. Sync logic must preserve this ownership boundary indefinitely and template changes must classify new files deliberately.

## Revisit Conditions
Revisit individual file ownership only when operational evidence shows that a file's semantic owner has changed. Do not move a file between classes merely to simplify one migration.

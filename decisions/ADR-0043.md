# Seal qiven-host and qiven-dcr-win; RuntimeHost absorbs the execution-authority role

## Context

After the Runtime program landed (ADR-0038/0039, Component ADL, C++
design), the owner re-audited the P layer (product infrastructure) and
found both remaining members redundant:

- **qiven-host** was conceived (ADR-0026) as a separate JasonPC
  execution-authority broker arbitrating multiple mutating AI flows
  after the 2026-09-16 DCR split-brain incident. The Runtime topology
  changed the premise: RuntimeHost is the single trusted, governed
  dispatch path; with DCR retired there is no second competing flow to
  arbitrate, and the single-writer problem collapses into RuntimeHost's
  own multi-instance/restart protection.
- **qiven-dcr-win** existed to drive the paid Desktop Commander MCP
  (https://mcp.desktopcommander.app/) because ChatGPT chat mode could
  not use MCP directly - a workaround of a superseded agent selection,
  with a recurring cost on top. Its native-supervisor implementation
  was never required by anything else.

## Decision

1. **qiven-host is sealed** (cloud preserved, sealed README, local
   working copies removed). Its ADR-0026 invariants - single-writer
   lease, monotonic fencing epochs, fail-closed quarantine,
   reconciliation, bounded execution journal - are ABSORBED as
   RuntimeHost-internal subsystem semantics, implemented behind the
   already-designed `IExecutionAuthorityPort` (runtime C++ design
   §8.5). The "conjunctive orthogonal gates" invariant of ADR-0038 §9
   is unchanged in MEANING: cognitive admission and execution
   authority remain separate gates; both now live inside the one
   trusted RuntimeHost process boundary instead of two processes. A
   direct mutating path around RuntimeHost remains a safety defect
   (ADR-0038 §44 wording preserved by substitution).
2. **qiven-dcr-win is sealed** (same treatment). The DCR transport
   program is retired; the DCR transport contract
   moves to the museum (`legacy/collaboration/`) as historical evidence (the split-brain
   incident evidence it preserves remains canonical history).
3. **Material sunk one layer down**: dcr-win's `process_generation`
   implementation (Windows Job Objects, pipe drainage, owned child
   trees) is the seed of the future `qiven-process` layer (ADR-0039
   §1; archived ADR-0025 scope). The code stays readable in the sealed
   cloud repository; `projects/process` records the provenance; no
   code moves to foundation (process supervision is policy-rich and
   below products, above foundation - exactly the qiven-process slot).
4. ADR-0023 (DCR-before-CAD sequencing) and ADR-0027 (host kernel
   acceptance separation) are archived to `decisions/legacy/`
   (subjects retired); ADR-0026 is archived with its invariants
   explicitly preserved by absorption into this decision and the
   Runtime design. OBL-20260915T163500Z-9D4C72 (DCR suspension) is
   archived as moot.
5. Repository inventory, roadmap, paused-work and project models are
   updated; the qiven-runtime Component ADL §44/45/§82 and the C++
   design §8.5 carry dated amendment notes pointing here.

## Alternatives Considered

Keeping host as the Runtime's authority service (rejected: two
processes where one trusted process suffices; the broker's arbitration
premise died with DCR); absorbing execution authority into foundation
(rejected: authority is policy, not a primitive); deleting the cloud
repositories (rejected: sealed history preserved per museum policy);
keeping dcr-win for future MCP bridging (rejected: the bridging need
died with the agent-selection change; recurring cost for zero
consumers).

## Consequences

The P layer is empty; the layer map simplifies to shared layers +
cognition plane + products. Machine-local governed mutation now means
"through RuntimeHost's authority subsystem", landing with the Runtime's
real-adapter batches. The split-brain incident's lesson is preserved as
RuntimeHost restart/multi-instance design input (RCA-12/19).

## Revisit Conditions

A second governed mutation channel ever appears (a second trusted
host process or a non-Runtime mutation path) - the lease/fencing
subsystem must then treat it as a competing writer per the absorbed
ADR-0026 semantics; or MCP-less chat harnesses return as a real
constraint (re-evaluate transport bridging then, not by reviving DCR).

## Provenance

Owner-directed P-layer audit 2026-09-21, immediately after the
one-turn C++ design landing.

# Harness-native background execution as the default session path; exec scoped to custody classes

## Context

Two intertwined defects motivated this decision (owner direction, v24
session, 2026-09-24):

**1. The exec detour is a token-economy defect.** The 2026-09-23 routing
architecture (registry + router v3) denied long-class raw commands and
instructed the model to start a `qiven exec` run and poll
`qiven exec status`. Every poll is a full LLM round-trip that re-sends
the live session context; supervision of one long command therefore
costs `O(polls x context-size)`, which in a long session dominates the
cost of the work itself. The same defect shaped the user-level
`run_in_background` prohibition (foreground + redirect + sleep/tail),
which is an equivalent polling loop that also blocks the turn. The
original motivations were real but were already solved elsewhere:
unbounded remote-CI observation is prohibited by the
explicit-dispatch-only CI law (MEM-20260921T095600Z-C5E1A8), and
session-shell death killing real commands is solved by custody, not by
polling. The two instruction layers additionally contradicted each
other (user-level: never background; workspace router: detour to exec),
taxing every retry.

**2. The exec leak recurred because the custody rollout is unfinished.**
The owner again observed lingering MSBuild and cmd-window processes and
concluded exec v2 "still unusable", blocking the MVP-4 H1 rerun.
Evidence: qiven-runtime still pins the v1 operator snapshot (template
0.1.8; exec records carry no custody identity), the v23 session ran
five MSBuild builds there under v1, and v1 has no Job Object, lease, or
completion reap - exactly the unbounded-descendant class ADR-0048
eliminated in devkit/qiven-context and OBL-20260923T234500Z-B9C1D3
tracks for the siblings. exec v2 itself is healthy (devkit runs show
clean custody receipts); it was never actually protecting the repo
where the builds happen. (v25: the rollout is now COMPLETE across the
workspace — see Decision 8.)

Platform facts established by live probes (2026-09-24; v24 session facts
re-verified or corrected by fresh-session probes in v25, same day):

- ZCode's Bash tool natively persists oversized foreground output
  (>~25-30KB) to a file and returns a ~2KB preview plus the path
  (probed in v24; carried, display-path behavior).
- ZCode's `run_in_background` returns an output-file path immediately
  and re-invokes the model exactly once on completion (task
  notification) — **verified live in a fresh session (v25 probe P1,
  2026-09-24T22:45Z)**, not merely documented.
- `TaskStop` kills the whole process tree, not just the primary (v25
  probe P2: background python parent + spawned ping child both dead
  after TaskStop; one "killed" notification, no polling).
- **The Bash `timeout` parameter does NOT bind background tasks** (v25
  probe P3: a 45s background task with `timeout: 6000` ran to natural
  completion; the v24 R1 mitigation line claiming the timeout bounds
  calls is corrected in Consequences below). Background bounding is:
  the command's own duration, TaskStop (tree-kill proven), and
  session-end semantics (probe P4 pending, next session).
- The deny -> re-call loop works naturally end to end (v25 probe P5:
  the session's first raw `qiven gate` call was denied with the exact
  re-call instruction; the guarded background re-call completed with
  one notification; also observed organically for sweep-class denials
  twice in the same session).
- ZCode hooks cannot rewrite tool input or tool output (PreToolUse
  returns a permission decision; PostToolUse can only inject
  additionalContext) - so a hook cannot silently fix a call; it can
  only deny with instructions.

## Decision

1. **Polling supervision of in-session long work is an anti-pattern.**
   The default session path for long-class commands is the harness's
   own background execution: one Bash call with
   `run_in_background: true`, an immediate output-file path, and one
   completion notification. No `qiven exec status` polls, no
   foreground `sleep && tail` loops.
2. **The hook router is the deterministic teacher** (router v4,
   qiven-devkit): a raw long/gate/network-class call is denied with the
   exact re-call instruction ("re-issue this command with
   `run_in_background: true`"). One denied call is the entire overhead.
   The deny -> re-call loop is the sanctioned pattern; the model
   choosing background unprompted remains welcome but is not relied on.
3. **Node-reuse custody guard on the background path.** Build/gate
   classes (anything that fans out MSBuild worker nodes) must carry
   `MSBUILDDISABLENODEREUSE=1` (env prefix) or `/nr:false` /
   `/nodeReuse:false`. The router denies the background re-call until
   the guard is present. This extends ADR-0048 clause 3 (defense in
   depth) from exec children to background-path children: no
   deliberate process survivors, because the harness notification fires
   at primary exit and would otherwise strand node processes.
   (v4.1, 2026-09-24: this guarantee is now mechanically real — the
   v4 `_GATE_CLASS` anchor did not tolerate the env-assignment prefix
   of the very re-call form this clause teaches, so any env-prefixed
   gate call escaped classification and the guard check with it; found
   live in v25, fixed in devkit with regression cases.)
4. **exec v2 scope (amendment to ADR-0048 clause 4 wording, not its
   custody law).** The Qiven Operator exec remains the single
   sanctioned mechanism for **survival-requiring** execution - runs
   that must outlive the session (durable receipts, cross-session
   work), owner-run kits and H1 packages (double-click entrypoints),
   lease-custodied sweeps (the ghost-process class), runs exceeding the
   harness Bash timeout ceiling (10 min), and unknown-duration work
   pending measurement. It is no longer the default agent path for
   ordinary in-session long work. ADR-0048 clauses 1-3, 5-6 are
   unchanged.
5. **Sweeps stay under exec custody** (deny -> exec, unchanged): a
   background task's lifetime at session end is not yet characterized
   (residual R1), and the 2026-09-23 ghost `find.exe` survived a
   session precisely through an uncustodied path. Revisit after the
   R1 evidence obligation lands.
6. **Oversized foreground output needs no custom insurance**: the
   harness persistence (file + ~2KB preview) is the mechanical bound,
   and no hook could implement it anyway (PostToolUse cannot rewrite
   tool results). Deliberate `> file 2>&1` redirection remains good
   practice for known-chatty commands; the preview + path is the
   safety net for the rest.
7. **One law, one layer (v25 correction).** The v24 landing treated a
   user-level `block-run-in-background` hook registration and a global
   `~/.zcode/AGENTS.md` as a standing instruction layer to be
   "deconflicted" (it rewrote the global AGENTS.md to carry this law).
   The owner clarified 2026-09-24 (v25): that user-level layer was an
   ACCIDENTAL configuration and was deleted by the owner personally —
   it was never a deliberate counter-instruction, and no user-level
   instruction layer exists. The carriers of this law are exactly:
   the canonical registry (`collaboration/long-command-registry.md`),
   the operating contract's long-command routing section, and the
   workspace hook router (the mechanical teacher). Nothing is written
   outside qiven-governed surfaces; rejection rollback does not touch
   user-level files (there is nothing to restore, by owner action).
8. **The custody rollout to siblings is COMPLETE (v25, correcting the
   v24 inventory).** The v24 text and OBL-20260923T234500Z-B9C1D3
   listed the v1 carriers as foundation, math, toolchain-win and
   third-party-win. The v25 workspace audit found the real inventory:
   qiven-foundation, qiven-math and **qiven-context-draft (missing
   from every prior list)** carried template 0.1.8 snapshots;
   qiven-toolchain-win and qiven-third-party-win carry NO operator
   snapshot at all (simple gate.cmd tooling, nothing to roll).
   All three real carriers rolled to 0.1.9 under delegated H2 in the
   v25 session (foundation PR #20 `f28b86b`, math PR #12 `518e511`,
   context-draft PR #40 `ea9af72` — customs re-applied byte-identical),
   plus the layer-contract ripple (runtime re-pins, PR #59). Every
   workspace qiven-* repository is now verified current; the leak class
   has no remaining armed carrier.

## Alternatives Considered

1. **Keep the exec detour, poll faster / teach better.** Rejected: the
   cost is the round-trips themselves, not their spacing or the prose
   around them.
2. **Behavioral-only fix (AGENTS.md tells the model to use
   background).** Rejected: attention-dependent, exactly the class the
   2026-09-23 heredoc recurrence already disproved; the contract is
   primary, the hook is the mechanical backstop (owner direction
   2026-09-23).
3. **A PostToolUse hook that rewrites oversized output to a file
   pointer.** Impossible in the platform (strict JSON schema;
   additionalContext only) - and unnecessary: the harness already
   implements the intent natively (probed 2026-09-24).
4. **A PreToolUse hook that silently rewrites the call** (auto-append
   the background flag or the env guard). Not supported by the platform
   (permission decision only). The deny -> re-call loop achieves the
   same guarantee for one cheap denied call.
5. **Machine-wide `MSBUILDDISABLENODEREUSE=1`.** Rejected: it would
   change the owner's interactive Visual Studio build behavior;
   the guard is scoped to agent-driven invocations (router-enforced)
   and exec v2 children (already injected, qiven_operator.py:651).
6. **Do nothing to the siblings (exec v2 "already landed").** Rejected:
   the owner-visible recurrence is precisely the v1 pin; the rollout
   obligation's trigger condition ("any session that plans heavy
   exec/gate usage there") was violated by v23 and must actually close.

## Consequences

- Token cost per long command drops from `O(polls x context)` to one
  denied call + one background call + one completion notification.
- The MSBuild node leak class is closed at both doors: exec v2 rollout
  (completion reap + injected guard) and the background path
  (router-enforced guard; nodes die with the primary).
- Residual R1 (narrowed by v25 probes, one fact open): background-task
  lifetime at SESSION END is uncharacterized (probe P4 prepared for
  the next session). TaskStop tree-kill and one-shot notification are
  proven; the `timeout` parameter does NOT bound background tasks
  (probed — the v24 mitigation line claiming it does is withdrawn).
  Standing mitigations: sweeps stay under exec lease (mechanical
  bound); build/gate background re-calls carry the node-reuse guard
  and are inherently-terminating commands; TaskStop is the proven
  mid-session kill.
- Background output files are session-scoped; durable evidence
  (gate receipts, merge proofs) still rides repository files and exec
  logs - delegated-H2 receipts are unaffected.
- The 10-minute harness Bash timeout ceiling becomes a routing fact:
  colder/heavier runs route to exec v2 (lease-bounded) instead.
- Hooks load at session start only: the mechanical flip (router v4 +
  user-level unblock) takes effect for sessions started after the
  config change; the flipping session itself finishes on the old
  regime (stable by construction).

## Revisit Conditions

- A background task is observed surviving its session (R1 fires) ->
  extend the sweep/detector to ZCode background tasks, or re-scope
  classes back to exec until the harness characterizes lifetime.
- TaskStop/tree-kill and session-end behavior get characterized (OBL
  below) -> sweeps may move to the background path.
- The harness grows PreToolUse input rewrite -> auto-inject the env
  guard instead of denying the re-call once.
- Measured billing contradicts the cost model -> re-measure and amend.

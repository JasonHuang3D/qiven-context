# Workspace Dependency Resolution: one generation-bound resolver as the dependency endpoint

## Status note

ACCEPTED 2026-09-24T11:26Z by owner adjudication in the v26 session
(the owner accepted qiven-docs PR #2 and directed the canonical landing;
the acceptance evidence is the owner statement cited in the frontmatter).
Acceptance covers the PROGRAM and its architecture/migration documents;
code-level implementation is deliberately deferred ("不急着落地代码层")
and tracked by the WR migration obligation. This ADR carries no
implementation claim.

## Decision

Qiven adopts the Workspace Dependency Resolution Program as accepted in
qiven-docs PR #2 (documents now at `accepted/2026-09-24/` in qiven-docs).
The normative content lives in those three documents; this ADR binds them
into Qiven canonical governance with the following scoping rulings:

1. **Partial supersession of ADR-0046, refinement of the rest.** The
   infrastructure layer model (toolchain -> devkit -> all repositories,
   Devkit-canonical engineering standards) REMAINS in force. The
   shim-plus-pin consumption pattern is reclassified from "target
   architecture" to "migration stage": the accepted endpoint is one
   explicit workspace resolver with an immutable WorkspaceGeneration
   lock (WG-1..WG-10; resolve-before-configure; one revision decision
   per node; thin launchers allowed, resolver shims forbidden). Until
   per-class WR cutovers land, shim-plus-pin remains the VALID current
   mechanism and no new shim-plus-pin resolver is added (doc 02 §1
   inventory law).
2. **ADR-0016 and ADR-0018 triggers.** ADR-0016's no-network
   local-source resolution is retained as a constraint INSIDE the
   workspace resolver (configure stays offline; resolution consumes
   local Git objects). ADR-0018 deferred workspace orchestration "until
   coordination or reuse is real": that condition has now fired (seven
   active repositories, mechanical pin-ripple PR chains measured in v25,
   an accepted TCA source closure requiring one exact multi-repository
   graph). The deferral ends with this ADR, bounded by the program's own
   stall mechanism.
3. **TCA boundary preserved (ADR-0050 unchanged).** CA-1 implements its
   already-accepted bounded source lock and ActivationGeneration on its
   own schedule; WR-0/WR-1 may run in parallel and are NOT CA-1 entry
   gates. TCA's repository selector migrates to WorkspaceGeneration only
   after WR-7 shadow equivalence and a separate owner-accepted
   governance amendment. The TCA source lock stays self-contained
   (commit/tree, path filters, per-file digests); the parent
   WorkspaceGeneration and operation-execution projection digests are
   provenance, never inputs to the activation content hash.
4. **Control-repository authority is two-step and budget-bounded.** The
   minimal qiven-workspace control repository is authorized ONLY after
   WR-0 delivers its sealed outputs (machine-readable census, the
   Profile B conflict fixture, the before-migration Profile J baseline,
   and a sealed WR-1/WR-2 effort budget) for owner review. Authoritative
   bootstrap additionally requires the independently accepted
   control-repository trust policy (an exact SHA proves identity, not
   authorization; unadmitted control revisions fail typed
   `UntrustedControlRevision`). Two missed stage exits or a budget
   breach pauses authority cutovers for an owner decision
   (continue-bounded / re-scope / abandon); shadow diagnostics cannot
   close the target-presence or pin-ripple defect classes while the
   legacy resolver remains authoritative, and a permanent stop records
   the residual instead of relabeling shadow mode as completion.
5. **In-force constraints untouched.** ADR-0048 process custody and
   ADR-0049 H1-kit self-containment bind whatever entrypoint lands;
   changed routed command forms are re-tested against the deployed hook
   router; changed H1 launchers/packages are re-tested for
   self-containment. ADR-0051 remains PROPOSED at acceptance time and
   its eventual owner decision is reconciled separately (doc 02 §8.8).
6. **Migration law.** The scheduling law of doc 02 §7 governs: WR stages
   proceed one dependency class at a time behind dual-resolution shadow
   proof; CA-1/CA-2 ceilings, MVP-4 H1/RR-0 prerequisites, and the CA-1
   stall trigger are unchanged; entrypoint integration checks (H1 kit
   working-directory/profile packaging, hook-router command anchors)
   are recorded as census scope items, not new dependency edges (the
   2026-09-24 MVP-4 H1 kit pre-flight incident is governed by
   ADR-0049's corrective lane, per the PR #2 §1.6 reclassification).

## Context

The accepted documents cite live repository evidence verified by two
independent reviewer LLMs across five rounds: consumer-local CMake
resolvers with exact SHA pins in runtime/draft/math; `if(NOT TARGET)`
gating that can suppress another consumer's dependency validation;
duplicated Toolchain discovery; the qiven-context Devkit pin (d1d2a3a)
diverging from Devkit main (223eaaa) while C++ repositories carry
managed Operator snapshots; raw `cmake -S` CI entry; the
unconditionally advapi32-linked sqlite3 package inside a multi-platform
CI matrix; and the v25 pin-ripple chain (foundation PR #20 -> math #12
+ draft #40 -> runtime #59). The 2026-09-24 MVP-4 H1 kit pre-flight
incident (kit `0.1.0-g6ebf6ff6`; CWD-dependent host profile default +
non-self-contained kit) contributes the entrypoint-hazard evidence
class; its sealed record is `evidence/audits/2026-09-24-mvp4-h1-kit-preflight-incident.md`.

## Alternatives Considered

- Keeping shim-plus-pin and teaching it better (attention-dependent;
  the defect is the distributed decision itself).
- Behavioral-only fixes (AGENTS.md prose) — disproven class per the
  2026-09-23 heredoc recurrence; the hook/gate is the mechanical
  carrier.
- Consumer-local `find_package`/package-manager discovery as the
  authority (ambient success, WG-3 violation).
- Monorepo consolidation (rejected; explicit closure does not require
  merging repositories).
- A public package registry / SemVer requirement for internal
  repositories (v1 non-goals).

## Consequences

- WR-0..WR-8 become a tracked canonical migration obligation with the
  program stall/budget mechanism (see obligations index, created with
  this ADR).
- Devkit owns the resolver implementation, schemas, validation rules,
  and generated CMake integration; the workspace control repository
  owns dependency-control data and bootstrap only.
- Governance audit cadence: this is the FIFTH ADR accepted since the
  2026-09-22 pass (0047, 0048, 0049, 0050, 0052) — the periodic
  governance audit recorded in state/current.md is now DUE.
- The first WR implementation batch is WR-0 only (census + Profile B
  fixture + Profile J baseline + sealed effort budget); qiven-workspace
  repository creation, schemas, and resolver code require the owner's
  review of those sealed outputs.

## Revisit Conditions

- The WR program stall/budget mechanism fires (two missed stage exits or
  an effort-budget breach, doc 02 §7.7) -> authority cutovers pause for
  an owner continue-bounded / re-scope / abandon decision; a permanent
  stop records the residual legacy defects and never relabels shadow
  mode as completion.
- WR-7 shadow equivalence fails or is not attempted -> the independent
  CA-1 source lock remains TCA's selector indefinitely; nothing in
  ADR-0050 weakens.
- The workspace trust-policy vehicle or the qiven-workspace repository
  shape proves wrong in WR-1 -> re-deliberate before any authoritative
  bootstrap; shadow/local inspection continues labeled.
- The harness or CMake grows a capability that changes the integration
  surface (e.g., governed package-config flows) -> re-deliberate the
  CMake adapter boundary before WR-3 cutover.

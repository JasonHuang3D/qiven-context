# Museum seal — kernel-semantic tests, retrieval and compiler tooling, and the record-lifecycle suite become non-executable legacy text

## Context

ADR-0040 sealed the Python ContextKernel's suites and gates but left the
code in place as executable files. On the same day the owner extended
the seal: everything semantically related to the kernel — the retrieval
stack (hybrid/semantic/structural/rerank/candidate-bundle), the context
compiler (R1) and its pack/input/evidence/snapshot modules, the
record-lifecycle suite (judged kernel-related: it tests lifecycle
semantics through the compiler and shares the sealed module family) — is
sealed on sight, and sealed executables are **disarmed**: moved into a
legacy museum folder and converted to Markdown whose body shows the
former source in fenced code blocks, so accidental execution is
physically impossible.

## Decision

1. `legacy/` is the museum root (`legacy/README.md` states the policy);
   `legacy/tools/<original-name>.md` holds each sealed executable's
   source as text with provenance headers (61 files, including the whole
   `tools/context_kernel/` package, retrieval/compiler/lifecycle modules,
   their 15 test suites, and the compile/retrieve/validate-candidate/
   bootstrap-semantic wrappers). No sealed file remains executable or
   importable.
2. The surviving validation path is self-contained: the repository
   validator's three kernel-family imports were extracted into
   `tools/record_support.py` (checked_yaml, mandatory_paths,
   lifecycle_errors); `tools/test.py` discovers record ids locally with
   lifecycle awareness. Validation continues through
   `context-local`/`context-docs` (now repository-validator,
   cold-boot-contract, windows-python-resolution + references/diff/clean
   — the record-lifecycle suite and the lifecycle-tests task are
   removed).
3. ADR-0022 (measured layered retrieval reliability) is archived to
   `decisions/legacy/` and superseded here: its measurement subject is
   the sealed retrieval stack. ADR-0003 is deliberately NOT archived:
   its subject — keep semantic source data simple with derived retrieval
   replaceable — remains law (constitution section 13 carries the same
   principle), independent of any implementation.
4. Task-specific retrieval at cold boot (BOOTSTRAP step 13) remains
   protocol; it is performed by the reading agent until the Runtime
   program provides the capability. The sealed entrypoint
   (`legacy/tools/retrieve_context.py.md`) is museum material.

## Alternatives Considered

Keeping sealed files executable with SEALED markers (rejected: markers
do not prevent accidental slow runs); deleting them (rejected: history
preserved as text, per the museum policy); archiving ADR-0003 too
(rejected: no material conflict — its principle survives).

## Consequences

No kernel-semantic code path can execute anywhere in the repository;
validation is repository-contract-only and fast; the museum preserves
the full historical evidence of the cost this surface carried. Future
retrieval/transport capability is Runtime work (ADR-0038 section 28).

## Revisit Conditions

Only by a new accepted ADR that names the exact capability to revive and
its Runtime-era justification.

## Provenance

Same-session escalation of ADR-0040 after the kernel seal still left
runnable semantic surfaces; dependency audit preceded the extraction so
no survivor imports museum material.

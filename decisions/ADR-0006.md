# Default local validation to FULL and allow FOCUSED only by explicit CTO scope

## Context
Local implementation needs a predictable Definition of Done without allowing jason-worker to silently reduce validation because a change appears small or unrelated.

## Decision
`FULL` is the default local validation profile. `FOCUSED` is permitted only when the CTO specification explicitly authorizes it and defines exact targets, tests, selectors, or commands. Focused validation must still cover the authorized Debug and Release configurations. Architectural barriers and cross-cutting infrastructure work use FULL unless explicitly overridden.

Before normal completion of a batch, the final stack tip receives full Debug and Release repository validation unless the CTO specification explicitly waives it. A local pass makes work eligible for CTO review; it does not mean the feature is accepted, cross-platform verified, or merged.

## Alternatives Considered
Allowing the implementation worker to infer reduced validation from the diff; using only Debug validation during development; treating a feature-level focused pass as sufficient batch-final evidence.

## Consequences
Validation cost is somewhat higher, but the policy avoids optimistic scope reduction and preserves a consistent safety floor. Explicit focused plans remain available when the CTO has enough context to define a narrower proof obligation.

## Revisit Conditions
Revisit if dependency-aware test selection becomes mechanically reliable enough to produce equivalent confidence and remains subject to explicit project policy.

Genesis reconstruction from the committed Foundation agent contract and worker protocol. Exact historical adoption time is not reconstructed here.

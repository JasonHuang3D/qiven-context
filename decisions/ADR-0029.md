# Require cryptographic local user presence for Host recovery authority

## Context

An owner-scoped Windows IPC ACL authenticates ordinary local access but cannot distinguish the owner's foreground recovery decision from a stale or competing transport process running under the same owner token. Allowing an ordinary client to clear `Reconciling` or `Quarantined` would defeat the fail-closed authority boundary.

## Decision

Recovery authority is independent of the Windows owner SID/token. The normal Host protocol exposes only Acquire, ExecuteTestOperation, Release, and QueryStatus; it never exposes Reconcile.

A separate recovery surface is limited to GetRecoveryChallenge, SubmitRecoveryAssertion, and QueryRecoveryStatus. The dangerous transition requires a Windows Hello/WebAuthn platform-authenticator assertion with user verification required. Host stores only the credential identifier, COSE public material, generation, and protocol metadata. Private key material remains non-exportable and authenticator-owned. There is no password, machine-file-secret, or owner-token fallback.

Enrollment exists only during trusted bootstrap. Loss or corruption fails closed and never triggers silent re-enrollment. Later rotation requires authorization by the existing recovery credential.

The canonical one-shot challenge binds protocol version, challenge id, broker boot nonce, persistent generation, fencing epoch, explicit authority state, recovery reason, requested `AbandonPriorAuthorityAndAdvanceFence` disposition, authority-state digest, journal-head digest, and a Windows-CSPRNG 256-bit nonce. It expires by monotonic in-process lifetime and is invalidated by use, state/fence change, or restart. Verification binds the expected credential and RP context, exact client data/challenge, signature, user-presence and user-verification flags, boot nonce, generation, epoch, and unused challenge. Authenticator counters are not Qiven replay authority.

On success Host durably abandons the prior execution/lease and advances generation and fence before returning Ready. Prior uncertain work remains classified uncertain; journal evidence is preserved. Old authority stays permanently stale.

Batch 000 proves this authorization and fencing transition but not reconciliation of external side effects. Batch 001 combines adapter evidence, owner review, presence authorization, and fence advancement. The threat addressed is split-brain authority, not an arbitrary malicious same-user process with unrestricted filesystem/process control.

## Alternatives Considered

- Treat the owner SID as recovery authority. Rejected because remote transport and foreground owner processes may share it.
- Expose Reconcile on normal IPC with an opaque file secret. Rejected because a same-user transport could obtain it and machine-file possession is not user presence.
- Silently re-enroll after credential loss. Rejected because it converts recovery failure into unauthorized authority reset.

## Consequences

Recovery is deliberately interactive and fail-closed. Automated tests use a cryptographically faithful authenticator behind the same narrow interface, while final JasonPC acceptance requires one real Windows Hello ceremony.

## Revisit Conditions

Revisit when Windows platform-authenticator guarantees change or another user-verifying non-exportable platform credential offers equal or stronger semantics.

## Provenance

Accepted after the Host worker identified that an owner-local pipe alone could not authorize recovery safely.

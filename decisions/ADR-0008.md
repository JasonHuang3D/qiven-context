# Make ownership, failure behavior, and allocation semantics explicit in Foundation

## Context
Foundation owns the lowest-level C++ resource and memory vocabulary used by later Qiven layers. Hidden allocation, ambiguous failure, implicit allocator provenance, or conflation of raw storage with object lifetime would propagate subtle bugs into every downstream repository.

## Decision
Foundation primitives make ownership, lifetime, allocation strategy, size/alignment, and failure behavior explicit. Ordinary control flow must not require exceptions. Checked arithmetic and checked conversion are used where overflow or representability would change allocation/bounds semantics.

The allocator boundary is a non-owning `AllocatorRef`; allocator backends outlive references and owners that depend on them. Raw storage ownership and C++ object lifetime are separate contracts. Allocation requests preserve size/alignment and deallocation provenance. Foundation does not provide a mutable process-global default allocator.

Owning primitives such as `OwnedAllocation`, `OwnedObject<T>`, and `OwnedArray<T>` preserve allocator provenance and deliberately distinguish allocation/layout failure from successful empty states where applicable.

## Alternatives Considered
Implicit process-global allocation policy; exception-based ordinary low-level failure; allocator-free owner types that forget deallocation provenance; treating raw storage ownership as equivalent to live-object lifetime.

## Consequences
Callers must carry more explicit state and respect backend lifetime contracts, but ownership and failure remain inspectable and testable. Higher layers can build richer policies without Foundation imposing a hidden global allocator or exception model.

## Revisit Conditions
Revisit individual APIs when concrete downstream requirements expose missing semantics, but preserve the explicit ownership/failure principles unless a stronger system-wide model replaces them deliberately.

Genesis reconstruction from the committed Foundation memory/ownership and failure-semantics architecture plus the repository agent contract.

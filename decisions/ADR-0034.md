# Separate remote cold boot from canonical artifact handoff and require lossless LLM transport compression after K4

## Context

Qiven had several distinct continuity mechanisms whose names overlapped: remote
fresh-session cold boot from canonical GitHub, bounded session checkpoints historically
called handoffs, K4 canonical export/restore, and Human Succession Acceptance.

The pre-correction K4 challenge let the same fresh agent fetch the candidate, run
export/restore, and then reconstruct project cognition. That can prove that a new
agent with canonical GitHub access can continue Qiven, but it does not prove that the
exported artifact caused continuity. A defective/incomplete export could be masked by
cognition reread from the remote repository.

ADR-0032 correctly removes duplicate JasonPC validation for portable Python/source
semantics. It does not imply that a machine or human role required by an acceptance
experiment may be removed. In K4, JasonPC can be an independent artifact producer;
that is experimental topology, not duplicate unit-test execution.

No later planned ContextKernel batch existed to repair this proof. Therefore the
handoff boundary must be explicit before K4 can be accepted.

## Decision

### Project Continuity is an outcome; delivery profiles are separate

`collaboration/project-continuity-acceptance.md` defines the semantic reconstruction
outcome. A concrete test must declare its delivery profile.

The admitted concepts are distinct:

- **Remote cold boot**: a fresh session reconstructs from an exact canonical remote
  Context ref plus admitted live evidence. This proves remote-context continuity.
- **Session checkpoint handoff**: a bounded session progress artifact under
  `sessions/`; useful continuity evidence, never canonical authority or a backup.
- **Canonical Artifact Handoff**: an independent producer creates one exact,
  self-describing Context artifact; an isolated fresh consumer reconstructs from
  that artifact before consulting canonical Context remotely. This proves portable
  artifact continuity.
- **Human Succession**: a different authorized human operator can take over without
  private recollection. This remains a stronger, separately invoked property.

Passing one profile never silently proves another.

### K4 must prove a causal artifact handoff

K4 acceptance uses the Canonical Artifact Handoff profile in
`collaboration/context-handoff-contract.md`.

The reference topology is:

```text
exact remotely published K4 candidate
        -> independent producer
        -> canonical export + verified continuity projection
        -> one self-describing handoff JSON
        ===== handoff boundary =====
        -> fresh consumer with no prior Qiven project memory
        -> reconstruction verdict
        -> only then: live verification of facts that are live by contract
```

Under the current `ContextView<ChatGPT, Jason>`, the acceptance producer is JasonPC
through Human Manual Mode/Qiven Operator. The producer records exact commit/tree,
platform/runtime, manifest/package/handoff digests, restore completeness and output
identity. This JasonPC role is not a second portable Python validation gate.

Before sealing its initial reconstruction, the consumer may not use the original
`qiven-context` repository, a prior Qiven chat, model-native project memory, the
producer's oral/private reconstruction, or an evaluator answer key to fill cognition.
The handoff artifact must be self-describing for the declared consumer profile. If
project-specific decoder material is necessary, it is part of the versioned handoff
artifact/profile and cannot be fetched as hidden context.

After reconstruction is sealed, the consumer must identify which assertions are live
facts and may verify those against GitHub/CI/runtime. Live verification may confirm
or update mutable external state; it may not repair missing canonical cognition in
the handoff artifact. Needing such repair is a K4 failure.

### K4 JSON is correctness-first, not token-optimal

K4 may deliberately use a verbose JSON representation. It must preserve the complete
canonical export and a deterministic, integrity-bound continuity projection that a
fresh LLM can inspect without project-specific repository reads. K4 acceptance is
about causality, completeness, integrity and isolation, not compression ratio.

### K5 is lossless semantic transport compression

After K4 is accepted, K5 implements a token-efficient transport representation for
LLM consumption. K5 is not task-specific retrieval, summarization or relevance
selection. It may change syntax, key vocabulary, framing, dictionary layout, coding,
or another reversible representation, but it must not change the recovered semantic
closure.

K5 acceptance requires both machine equivalence and cognitive equivalence. Machine
equivalence deterministically reconstructs the exact K4 handoff semantic closure and
fails closed on corruption, truncation, dictionary/version mismatch, ambiguity and
resource abuse. Cognitive equivalence uses isolated paired fresh-LLM trials to recover
the same required Project Continuity facts, protected constraints, negative knowledge,
abstentions and next legitimate action as the K4 reference.

A claimed token improvement must name the tokenizer/model family or tokenizer suite
used for measurement. Decoder instructions, dictionaries and framing that consume
LLM input count toward the budget. Byte compression alone is not evidence of token
compression. No external mutable dictionary or hidden model prompt may be required.

### Authority remains separate

Export, handoff, decode, restore, successful continuity, or compression never grants
mutation authority. GitHub remote remains canonical until a separately accepted
cutover decision says otherwise.

## Alternatives Considered

1. **Keep the old K4 fresh-session prompt and call remote cold boot sufficient.**
   Rejected because the consumer can reacquire cognition from the source repository,
   so the export artifact is not causally tested.
2. **Require JasonPC to rerun every portable Context test.** Rejected because it
   confuses artifact-producer topology with duplicate implementation validation and
   contradicts ADR-0032's scoped efficiency rule.
3. **Compress before establishing the uncompressed K4 reference.** Rejected because
   semantic loss would be difficult to distinguish from an existing handoff defect.
4. **Use ordinary ContextBundle retrieval as K5 compression.** Rejected because
   relevance selection is intentionally task-bounded and can omit canonical material;
   K5 must be lossless with respect to the complete handoff semantic closure.

## Consequences

K4 must be corrected before acceptance rather than relying on the earlier
remote-cold-boot-shaped challenge. Existing remote-cold-boot evidence remains valid
for the property it actually proved, but cannot be cited as K4 artifact portability.

K5 becomes the next ContextKernel optimization boundary after K4 rather than an
implicit implementation detail. Correctness and portability remain ahead of token
optimization while token efficiency becomes a measured engineering property.

## Revisit Conditions

Revisit the handoff topology if the product gains a trusted first-class artifact
transport that can enforce consumer isolation more strongly than manual transfer.
Revisit K5's codec strategy when real tokenizer/model measurements show a different
representation dominates, but do not weaken lossless machine equivalence or isolated
cognitive equivalence without a new accepted decision.

Revisit whether K5 remains a distinct batch only if a future transport can prove
strictly lossless token reduction as an intrinsic K4 representation without mixing
correctness and optimization acceptance.

## Provenance

Accepted from the project owner's 2026-09-18 direction after a read-only review of
K4 candidate `232e26cf04182ed6627d8e400ff161231b220e85` identified that the existing
fresh-session prompt inherited the older GitHub remote cold-boot topology. The owner
explicitly authorized correction of existing Context material and required a later
strictly tested semantic-preserving token-compression stage.

This ADR amends ADR-0033 without superseding its representation-independent
ContextKernel architecture, transaction semantics or authority-cutover boundary.

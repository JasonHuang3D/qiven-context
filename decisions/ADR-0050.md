# Task Cognition Activation and Independent Falsification

## Context

The MVP-4 owner-live H1 sequence failed three times on mature, known hazard
classes (an assumed external payload field; a dangling non-owning byte view;
an unavailable fail-closed mediator with an undifferentiated denial and an
unobserved connection contract). Existing project cognition already
contained the governing laws; they were stored, not activated, and the
authoring context could reproduce its own assumptions in code and tests
until the owner supplied the first independent reality check. The same
interval produced the owner's consumer-first finding: the documentation
system was governing the LLM rather than equipping it — 21 sessions of
deliberation infrastructure without one consumer report of degradation.

The owner authored four governance proposals (00-03) establishing a Task
Cognition Activation (TCA) capability; a three-model, seven-pass
cross-LLM deliberation on qiven-docs PR #1 (corrections R1-R15) converged
them. This ADR records the decision that program body carries; the four
documents are the normative detail and land canonically per this ADR.

## Decision

1. **Four claims, separately proven.** Project Continuity, Activation
   Correctness, Cognitive Utility, and Mechanical Governance are distinct
   claims; passing one never silently establishes another.
2. **Native deterministic activation.** A Runtime-side
   `TaskCognitionActivator` compiles an immutable, bounded, explainable
   `TaskCognitionBundle` from a pinned canonical bundle, an exact
   multi-repository source lock (`ActivationGeneration` sidecar, separate
   from the execution `RuntimeGeneration`), a normalized task descriptor,
   and the canonical activation policy. The production path is native and
   local; it must not call an LLM, embedding service, or network service
   for protected selection.
3. **Protected applicability.** Critical hazards and binding constraints
   use deterministic applicability selectors; ranking may never remove
   them; unknown applicability fails visibly. Protected-class canonical
   records carry selector metadata from creation (bootstrapped before gate
   enforcement).
4. **Canonical/derived separation.** Activation indexes, bundles, and
   receipts are rebuildable derivatives bound to exact source revisions
   and digests; canonical truth remains Git-backed; SQLite is never domain
   truth.
5. **External task-boundary triggering, non-vacuous.** Activation
   originates at observed task boundaries, and the before-design claim
   requires a qualified, real model-visible ingress that delivers the
   exact bundle before the first design output, with captured ordering and
   withheld/altered/late delivery rejection. CA-2 cannot pass with an
   empty coverage set; uninstrumented dogfood work is a coverage failure.
6. **Independent falsification for R2/R3.** High-risk correlated
   assumptions are challenged by evidence not generated from the author's
   reasoning path. Two disclosed independence classes: routine R2 may use
   a harness-created fresh isolated-context session; every R3 review,
   Profile C trial, and CA-5 review uses independently orchestrated
   isolation.
7. **Explicit ADR-0036 / human-handoff-boundary amendment (R7).** Adopting
   the owner-free transport model amends the contract, not a
   reinterpretation: mechanically verified session creation, sealed input
   transport, and sealed output capture inside an approved orchestration
   boundary cease to be inherently H1. H1 remains mandatory for owner-only
   credentials or devices, external isolation boundaries the orchestrator
   cannot cross, owner-named trust anchors, and owner-designated
   adjudication. Existing owner-named K4/K5 gates and all H2-H4 claims are
   unchanged. Until this ADR is accepted and the contract text amended,
   the current H1 classification remains authoritative.
8. **Sequencing.** Freeze substantive MVP-5. Start CA-0 immediately; a
   strictly bounded MVP-4 corrective lane reruns the real H1 gate; RR-0
   (byte-representation remediation — separately admitted under ADR-0024,
   evidentially independent of TCA) completes in the same interval. CA-1
   begins only after CA-0, MVP-4 H1, and RR-0 pass; CA-2 before
   substantive MVP-5. MVP-5/MVP-6 dogfood the accepted path (CA-3/CA-4).
   MVP-7 requires BOTH the original Runtime Control Gate and the separate
   Cognitive Utility Gate.
9. **The sealed Python ContextKernel/compiler/retrieval system stays
   sealed.** No production TCA path revives it; the former ~300-second
   write-coupled gate model is rejected; canonical mutation, cognition
   publication, and task activation remain separate transactions.
10. **Scar lifecycle.** Material incidents proceed
    Observed → Recorded → Classified → ActivationBound →
    MechanicallyEmbodied → RegressionProven → PromptRetired; recurrence
    after an active scar forces a control review, never another prose
    warning alone.

## Alternatives Considered

1. Compress the manual corpus now and discipline sessions to sweep it:
   rejected — manual selection is the exact failure class (the 2026-09-23
   heredoc recurrence); subtraction before proven coverage loses protected
   rules.
2. Fix MVP-4 locally and continue MVP-5 (MVP-4.1): rejected — repairs the
   instances while preserving the producing mechanism.
3. Move every repeated byte concept into Foundation as a CA-1
   prerequisite counted as TCA evidence: rejected (deliberation R1) —
   evidence contamination; RR-0 is separately admitted and separately
   evidenced.
4. Owner-relayed fresh-review transport for milestone trials: rejected
   (deliberation R2/R7) — the owner becomes a routine transport layer;
   replaced by the explicitly amended, owner-free orchestration classes.

## Consequences

- The interim is heavier (receipts, compliance maps, falsification
  evidence on top of the unreduced manual path) until replacement
  acceptance; transition discipline (bounded CA-1 batch with an
  evidence-based stop condition; expiring declared program packs) bounds
  it.
- The manual active-memory-title sweep and mandatory boot prose shrink
  ONLY after the acceptance protocol's replacement criteria pass; rollback
  to the last accepted generation is part of acceptance.
- Cognitive-amplification claims require the paired fresh-consumer
  protocol (sealed fixtures, condition-blind descriptors, delivered-token
  accounting, sealed sequential statistics); K5 compression and semantic
  reranking stay deferred until the uncompressed reference passes.
- Canonical landing (per deliberation R6): qiven-context-owned documents
  land in the acceptance transaction; qiven-runtime-owned documents land
  as separately validated commits bound by exact revision; the qiven-docs
  deliberation copies stay under accepted/2026-09-23/ as the deliberation
  record.

## Revisit Conditions

- A supported harness ingress for model-visible pre-design delivery is
  proven or blocked by CA-0 capture; a blocker re-deliberates sequencing
  rather than silently substituting publication-time receipts.
- The handoff-contract amendment text (Decision 7) is applied to
  `collaboration/human-handoff-boundary.md` in the acceptance transaction.
- Post-MVP-7, per the roadmap amendment §7.4: prompt retirement, capability
  extraction assistance, renderers, incremental index publication, optional
  semantic reranking, K5 compression — none inherits the Cognitive Utility
  Claim automatically.

# Permit jason-brother to merge exact validated batch heads after local validation evidence

## Context
The original workflow required the project owner to execute machine-local validation and report the result because jason-brother had no direct JasonPC execution path. Qiven-v4 accepted Desktop Commander Remote (DCR) as a bounded executor/transport that can run the same pre-decided local validation on JasonPC and return auditable output directly to Chat. Requiring an additional owner relay message after the same exact-head validation is already observed through the accepted DCR path would preserve ceremony rather than authority.

## Decision
For Qiven batch work, jason-brother has standing authorization to merge the batch branch into `main` after all required gates for that batch are satisfied.

For qiven-context portable Python/source-contract work only, the scoped validation exception in ADR-0032 replaces the machine-local requirement below. Exact candidate review and relevant validation still apply.

At minimum:

- required machine-local validation must pass on the exact branch head proposed for merge;
- local validation evidence may come either from the project owner's foreground execution/report or from jason-brother directly observing the exact-head run through the accepted bounded DCR execution contract;
- jason-brother must perform exact remote review of the head/delta before merge;
- any required remote CI or other batch-specific gate must also be green;
- if the branch changes after the validated head, the changed head must be validated again before merge.

A DCR connection by itself is not validation evidence. The run must bind to the exact candidate head, use the accepted execution/environment contract for the required capability, preserve truthful exit semantics, and complete the required gate. Human CMD remains a valid fallback and the project owner may revoke or narrow this authorization at any time.

The merge must not use force-push or bypass required validation. A normal no-fast-forward batch merge is preferred when preserving the batch boundary is useful.

## Alternatives Considered
Require a separate user `all pass` relay even after an accepted DCR exact-head run; allow jason-brother to merge before local validation; treat a previously tested ancestor as sufficient after later branch changes; treat DCR connectivity alone as proof of machine-local validation.

## Consequences
The project owner retains project/release authority while repetitive validation relay turns can be removed. Exact-head binding prevents remote edits after testing from silently entering `main`. The accepted DCR path improves long-session throughput without turning DCR into autonomous engineering authority.

## Revisit Conditions
Revisit if the user revokes or narrows this authorization, if DCR's execution boundary materially changes, or if a future automation layer replaces the current auditable local-validation gate.

# Session continuity evidence

Session records bound volatile loss after a chat/session incident. They are not canonical project truth and are not transcripts.

Active checkpoints use `YYYY-MM-DD-qiven-vN.md` and record the session identity, exact current task, accepted refs/evidence, unaccepted candidate refs, pending asynchronous work, known inconsistencies/evidence gaps, and exact next action.

Any cognition that must survive the session must be promoted into decisions, memory, obligations, projects, state, governance, or durable audit evidence.

Historical handoffs produced under the pre-v2 model are preserved in `sessions/legacy/`. Missing Qiven-v2 through Qiven-v5 session records are an evidence gap and must not be fabricated.

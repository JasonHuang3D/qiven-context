# Human-in-the-loop waits are event-driven or blocking, never polled

When a turn needs a human action (a GUI click, a manual run) before
the LLM can continue, two ZCode-native mechanisms already exist:

1. **`AskUserQuestion` (blocking interactive wait).** The tool call
   presents the instruction to the owner and the turn suspends until
   they answer; the LLM resumes with the answer in-context. This is
   the correct primitive whenever the "trigger event" is the owner
   replying (including "I clicked it - done"). No polling, no file
   races, no token burn.
2. **Background watcher + single completion notification.** When the
   trigger is a machine-observable event (a file appearing, a process
   spawning, a log line), run a watcher as a `run_in_background`
   command that exits exactly when the condition holds (e.g.
   `while [ ! -s <file> ]; do sleep 2; done; cat <file>`). The
   harness notifies the LLM once on completion - the same
   notification-once law as ADR-0051's background execution. The
   watcher, not the LLM, does the sleeping; the turn ends and the
   notification starts the continuation.

The v30 anti-pattern (measured, do not repeat): a foreground
`for i in 1..N; do sleep 20; check-file; done` loop inside the turn.
It holds the turn hostage, re-reads a file that a concurrent writer
may be mid-writing (partial-read/TOCTOU undefined behavior), emits
heartbeat noise as its only output, and burns context tokens per
poll. If neither primitive fits (e.g. the event needs a long-lived
observer past the turn), that is a harness gap to raise with the
owner, not a reason to poll.

Standing rule: any design needing "LLM waits, then wakes on event"
composes these two - ask, or arm a watcher and end the turn. Validated
on ZCode Desktop only; other agent families are untested and must not
inherit this claim untested.

in `views/workflows/human-in-the-loop-wait.md`; the contract carrier is
`collaboration/operating-contract.md` §"Waiting on humans or external
events" (owner direction 2026-09-26 — the law, not this scar).

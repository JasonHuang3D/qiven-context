# A fixed temp filename is a shared fixture across the whole machine

`TempFile("qiven-rca3-pin-ok.bin")` in `std::filesystem::temp_directory_path()`
looks self-contained: create, read, destructor-remove. But the gate runs
test-debug ∥ test-release as SEPARATE PROCESSES: the two cognition-pin
exes used the SAME temp paths, and one process's destructor `remove()`
deleted the file the other's `pin()` was verifying - a 0.02 s verify
failure that never reproduces isolated. v23 recorded it as "transient,
correlated with the preflight's real-journal host boots"; the v24 sync
batch reproduced it deterministically twice (the foundation re-pin
reshuffled timings and widened the window), isolated it to
cross-configuration parallelism, and fixed it with per-process names
(the ipc_multiframe `GetCurrentProcessId()` pattern).

Lessons:

1. A fixed name under the system temp dir is a MACHINE-GLOBAL shared
   fixture. Any parallel executor (ctest configs, CI matrix, two
   checkouts) races on it. Uniquify per process (pid) or per
   configuration workroot - never fixed.
2. "Non-reproducible on re-run" flakiness inside a parallel gate is a
   fixture-race suspect FIRST (the F8A9B0 class), not an environment
   mystery: isolate (single-config run), then parallelize back to
   discriminate. One flake forgiven as "transient" is a race left armed
   for the next timing shift.
3. Misattribution has a cost shape: the v23 correlation (preflight
   boots) was coincidental timing; the deterministic discriminator
   (full suite alone vs in-gate) found the true cause in two runs.

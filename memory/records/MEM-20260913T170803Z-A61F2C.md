# Command presence is not interpreter availability on Windows

Windows may expose Microsoft Store aliases or other shims named `python.exe`, while a `py.exe` launcher may exist but be stale or unusable. Repository tooling must execute and version-check interpreter candidates instead of treating command presence as proof of availability.

Qiven tooling should tolerate messy host installations through repository-local discovery and pin all post-bootstrap work to `.venv`. Users should not need to clean or modify global host configuration for Qiven.

# Assumed external contracts never ship as REQUIRED; H1 kits are packages

The MVP-4 hook extractor REQUIRED a `session_id` payload field that the
real ZCode payload never carried (RCA-14 had already recorded the
absence; the live router proved only `tool_input.command`). Fail-closed
then blocked EVERY tool in the owner's live session. Three laws:

1. **Verify-then-require.** A field of an external contract (harness
   payloads, foreign schemas) becomes REQUIRED only after a recorded
   real-world capture proves it exists. Until then: identity flows from
   the TRUSTED REGISTRATION TEMPLATE (config-pinned flags), payload
   fields are corroborating evidence at most (a contradiction denies),
   and kits carry a capture/probe step (`--dump-stdin` class) so the
   real shape becomes evidence.
2. **H1 kits are packages.** An H1 acceptance point is a complete,
   tool-built, rollback-able package the owner's hands execute
   (deploy-like, via the H1 path): binaries, the exact ready config
   files (no owner authoring), double-clickable launchers, evidence
   collectors, rollback, and a GENERATED guide. Prose kits in docs/ are
   pointers at most. The ZCode UI review is the enable gate for
   live-environment configs — the session may write the file; only the
   owner's approval arms it.
3. **Owner-facing content is executable content.** Commands are
   shell-labeled and shell-correct (Git Bash is the ZCode session
   shell: `cd /d/...`, not `cd D:\...`); owner-facing binaries print
   staged boot output, every durable path they write, and a heartbeat
   during healthy silence.

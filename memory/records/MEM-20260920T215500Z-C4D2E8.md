# CMake divergence audit 2026-09-21 and the normalization program

Audit findings (the "multiple standards" the owner observed):

1. **Naming law vs reality**: naming-cmake.md required bare unprefixed raw
   targets (`foundation` under `qiven::foundation`) — NO repository
   followed it; all use `qiven-<name>` raw targets, with three alias
   styles (`qiven::foundation`, `qiven::dcr_win`, `qiven::context-draft`).
   The doc was the outlier, not the repos; foundation is normative.
2. **Header visibility** (the owner's VS2022 requirement) existed ONLY in
   foundation (`FILE_SET HEADERS` + VS-generator `source_group TREE`).
   dcr-win had FILE_SET without source_group; math/draft/runtime/host had
   neither — headers invisible in the solution explorer in 4 of 6 repos.
3. **Template families**: only cpp-library was supported; qiven-host sat
   on an orphaned cpp-app 0.2.0 family (with a QivenBuild/QivenTarget
   helper layer diverging from foundation's explicit-list pattern) that
   the sync tool refused; dcr-win had hand-grown app+test targets in its
   root CMakeLists against the structure law.
4. **Two committed python caches** (runtime merge, dcr-win roll) exposed
   missing `__pycache__` ignores in bootstrap gitignores.

Normalization executed (all gates PASS at exact heads):
- conventions updated — naming corrected to observed reality
  (`qiven-<name>` raw, snake_case alias component, app-target rules);
  cmake-usage gains the **header visibility law** (foundation reference);
- **cpp-app template family** implemented in devkit (shared managed
  surface via QIVEN_MANAGED_SOURCE_DIR + library/app scaffold; New takes
  `-DTEMPLATE`; Sync accepts both families; regression now CONFIGURES the
  generated example — caught a real alias bug the generation-only test
  missed);
- qiven-host migrated officially (0.2.0 → 0.1.5, helper layer removed,
  foundation-pattern app CMakeLists; OBL-E6B9D4 done);
- qiven-runtime re-scaffolded on cpp-app (RuntimeHost app target matches
  the Component ADL first-landing topology);
- math (6 headers), context-draft (4+2 files, alias →
  `qiven::context_draft`), dcr-win (source_group + tests/ extraction)
  normalized to the header-visibility and structure law.

Residual: foundation itself already conforms (it is the reference);
toolchain-win has no CMake. The bootstrap `.gitignore` template should
add `__pycache__/` in the next template revision (per-repo ignores were
patched individually).

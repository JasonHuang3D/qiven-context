# Per-config test workroots under parallel gate stages

The operator gate declares `[test-debug, test-release]` as a PARALLEL
stage: both ctest suites run simultaneously. Any test that materializes
fixtures under a fixed workroot path (`<repo>/.generated-temp/.../name`)
has its Debug and Release instances MUTATING THE SAME FILES — the race
is intermittent (single-suite runs pass; the full gate fails on the
re-entrant step), which makes it look like a flaky test instead of a
shared-path defect.

Fix at the registration point, not per test: the workroot compile
definition carries the configuration (`$<CONFIG>`), so every suite
instance owns an isolated fixture tree. Applied to the whole journal +
MVP-2 test family at once — the MVP-1 tests carried the same latent
exposure and never lost the race only by timing luck.

Law shape (constitution section 17): two test processes failing only
under parallel staging is a fixture-ownership defect, not test noise —
diagnose the sharing, do not re-roll.

# DCR Git SSH on JasonPC requires ProgramData restoration because its Windows environment whitelist omits it

Desktop Commander Remote 0.2.50 launches its local MCP server with a Windows safe-environment whitelist that propagates `USERPROFILE` but omits `ProgramData`. On the accepted JasonPC environment, Windows OpenSSH 9.5 exits `255` before normal SSH config, network, proxy, key, or host-key processing when `ProgramData` is absent.

Controlled probes isolated this dependency: restoring only `ProgramData=C:\ProgramData` changed the OpenSSH probe from exit `255` to success. Human foreground CMD already has this variable, which explains why the same Git/SSH path worked there while the earlier DCR child failed.

For DCR-launched Qiven Git/SSH operations, establish `ProgramData=C:\ProgramData` process-locally before invoking Windows OpenSSH. Also use the absolute SSH executable and config path plus batch/no-password options. This is an execution contract, not permission to weaken SSH ACLs, host-key checking, credentials, or proxy/security configuration.

Work acceptance also proved that DCR can be self-started in the active `JASONPC\<os-username>` session without owner credentials, a service, scheduled task, persistent elevation, or startup persistence; DCR children run under the owner token/session rather than the restricted Codex sandbox token. The exact DCR process tree must be tracked when self-managing lifecycle.

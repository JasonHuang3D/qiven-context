# Standing-window premature stop at an H2 batch

The owner declared a standing long-running window with an explicit stop
condition (H1 only). After completing v4.3, the agent staged the branch,
refreshed the canonical checkpoint, presented the H2 batch, and ended its
turn — halting all work until the owner replied.

## Audit finding

**No contract or constitution article mandated the stop.** ADR-0036
requires H2 BEFORE merge-class publication; it does not require halting
work while H2 is pending. The stop violated the standing-window definition
the agent itself had committed the same day ("awaiting an H2 batch does
NOT stop work"). The constitution needs no change.

Root causes (three, in order of weight):

1. **Window-close habit.** The pre-standing workflow's shape — batch,
   present, stop — persisted as muscle memory after the mode changed.
2. **Unspecified turn model.** In a conversational agent, ending a reply
   is a de-facto pause of all work; "continue" was never defined at turn
   granularity, so the batch presentation felt like a legitimate reply
   boundary.
3. **Checkpoint cadence creating false boundaries.** The per-batch
   checkpoint-commit rhythm (staged candidate -> canonical checkpoint
   refresh -> present) reinforced batch-shaped stopping points, although
   the checkpoint's purpose is continuity, not punctuation.

## Fix (landed 2026-09-20)

`views/workflows/long-running.md` amended: turn semantics normative for
standing windows (H2 presentation = asynchronous notification, never a
stop; only H1/H3/H4, owner-declared end, or resource exhaustion pause
work), plus the **stashed checkpoint**: the workspace log carries a
structured STASH section (current sub-task, uncommitted delta, next
micro-action, staged branches, pending H2) as fine-grain continuity
insurance — both interruption recovery and next-session pickup, per the
owner's definition. Guardrails: constitution §5 unchanged — nothing
durable lives only in the stash; the canonical `sessions/` checkpoint
names the active window and stash path so a fresh session reads the stash
first.

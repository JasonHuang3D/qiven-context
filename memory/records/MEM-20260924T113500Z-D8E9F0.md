# Boot-class event queries prove less than they appear on Modern Standby

On this JasonPC (Modern Standby), "no reboot since X" from boot-class
events (EventLog 6005/6009, User32 1074, Kernel-General 12/13) does NOT
mean the machine was continuously up: owner power-downs travel as
suspend-class transitions (Kernel-Power 42/187 with Sleep Reason, wake
as 107, plus Power-Troubleshooter Id=1 carrying authoritative Sleep/Wake
timestamps), and hiberboot resumes update none of the boot counters.
Any uptime-dependent conclusion - process-lifetime probes, "the machine
was awake" claims, incident-window reasoning - must query the suspend
timeline in the same breath. Second, reusable mechanism: a Modern
Standby suspend FREEZES user processes rather than killing them, so a
process alive at suspend completes its remaining wall-clock waits shortly
after wake; "no output long after wake" therefore proves death BEFORE
the suspend. The P4B probe protocol (OBL-D5E6F7) bakes both rules in:
the power timeline is a mandatory part of every read-out.

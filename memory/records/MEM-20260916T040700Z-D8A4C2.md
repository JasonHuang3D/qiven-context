# Persist fail-closed authority transitions even when the triggering request is rejected

A rejected request is not evidence that authority state was unchanged. Validation or ownership checks may deliberately transition the authority machine into a stronger fail-closed phase such as `Quarantined` before returning an error to the caller.

The first `AuthorityBroker` orchestration checkpoint correctly changed in-memory state to `Quarantined` when a competing session attempted `Release`, but the broker's rejection path initially journaled the rejection without persisting the changed phase to `FenceStore`. Cross-platform CI was green; exact remote semantic review found the omission before acceptance. The corrected checkpoint persists any rejection-induced phase transition before appending rejection evidence, and a Windows restart test proves that `Quarantined` survives broker replacement.

For Host authority code, every operation must compare pre/post authority phase independently of success/failure classification. If a failed or rejected request changed durable authority semantics, persist the fail-closed state before returning or relying on journal evidence. CI is proof of tested behavior, not a substitute for reviewing persistence ordering and crash semantics.

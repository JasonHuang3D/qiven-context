# No silent detours around tooling defects

When an owned tool path (Operator subcommands, hook router, gates,
repository tooling) fails or behaves anomalously — empty logs, popup
windows, wrong exit codes, mangled quoting — the session treats it as a
DEFECT with exactly two lawful responses: root-cause and fix it in the
owning repository (regression tests carry the fix), or stop and escalate
to the owner (exiting the turn if needed). Silently switching to an
alternate entry path so work continues is PROHIBITED even when the
produced work is correct: the defect stays armed for the next session,
the anomalous behavior falsely looks solved, and the owner loses
visibility into their tooling's real state. A temporary detour exists
only as an explicit, recorded owner decision.

Governing incident (2026-09-23): `qiven exec` on `.cmd` targets produced
empty run logs, popup consoles and `0xC0000142` failures; the v18 session
switched its gate runs to the `python` entry point instead of
root-causing. The owner later OBSERVED the popup windows (a symptom the
session could not see), ordered the audit, and the real fix
(`CREATE_NO_WINDOW`, devkit 9fe34c1) landed with a full regression
suite. The detour had masked all of it.

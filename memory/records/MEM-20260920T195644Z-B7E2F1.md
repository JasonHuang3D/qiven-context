# Gate-cost optimization beyond fail-fast deferred to the Runtime program

2026-09-21 gate review measured the full `context-local` gate at
241-258s wall, dominated by the corpus-bound `context-kernel-k4` archive
suite (257.99s; `context-kernel-k3` reads 182.5s next), with no
first-failure early exit and cheap checks ordered after the expensive
batch (a 0.84s cold-boot-contract failure cost a full cycle).

Of the proposed optimizations, P1 (fail-fast ordering + early exit),
P4 (per-task durations in receipts) and P5 (ambiguous "(FAIL)" mode
label) landed as one tools batch. **P2 (delta-aware gate selection in
merge-proof) and P3 (kernel-suite export dedup/fixture work) are
deferred** by owner direction:

- P3 optimizes the Python context-kernel reference implementation whose
  production successor is the Runtime program (ADR-0037 draft is the
  executable specification; ADR-0038 names `RunMechanicalCheck <- actual
  gate/check execution` as a Runtime resolver class).
- P2, although operator/workflow policy rather than kernel semantics,
  hand-builds delta-aware mechanical-check selection in the incumbent
  operator — the exact mechanism class the Runtime will own as
  InvocationPolicy data. Building it now would be a weaker local copy at
  the wrong owner (software-engineering-philosophy section 1).

Accepted interim cost: every merge-class publication keeps paying the
full gate (~4 min, growing with corpus). Revisit trigger: if the full
gate wall time becomes operationally intolerable (rough ceiling: ~8
minutes) before the Runtime subsumes mechanical checks, revisit P2
narrowly as a stopgap — never as the long-term mechanism.

Amended 2026-09-21 (owner direction, same session): the interim cost
above was superseded the same day by a static gate split — kernel-
semantics suites (ContextKernel/compiler/retrieval/archive/handoff)
were removed from the default `context-local` gate, which now runs the
repo-contract suites only; a separate `context-kernel` gate (all
suites, `merge-proof-kernel` receipt) is required only for
tools/kernel-path changes. This is a static scope split by workflow
rule, not P2's automated delta-aware selection, which remains deferred.

# Borrowed views over temporaries dangle across delayed boundaries

MVP-4 H1 trial 2: `HookRun` held the payload as `std::span<const std::byte>`
assigned from the temporary returned by `read_stdin_verbatim()`; the
temporary died at the semicolon, the span dangled into freed heap, and the
extractor read garbage (raw pointers, not JSON) — one symptom (deny 118)
shared by two coexisting bugs, the first fix correct but not sufficient.

Law: when construction and later use happen at different times, the type
that stores the work across the boundary OWNS the bytes (`std::vector`,
owning buffer), never a view; a view is a rental contract with an explicit
outlives relation, not storage. The semantic owner is the Runtime/domain
type that keeps the work alive, not a lower-layer wrapper. Tests must
exercise the delayed/stored path — an immediate-use test cannot see a
dangling view — ideally under a lifetime-sensitive detector (ASan) or an
adversarial construction that reuses the freed region. Two independent bugs
can share one symptom: fix, then re-attack the symptom before declaring
victory.

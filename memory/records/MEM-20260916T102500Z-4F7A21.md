# Qiven Operator is the shared local execution interface for both human manual mode and Host-driven AI execution

Qiven should not make the project owner repeatedly interpret ad-hoc CMD chains, PowerShell scripts, Python scripts, or temporary clones. Devkit Operator already owns the local engineering interface: state-oriented progress, color, final summary, exact Git validation, task isolation, fail-fast gates, and machine-readable automation output.

The general engineering invariant is shared Operator semantics: human-triggered and Host-triggered local execution use the same task/gate surface, while authority and caller differ. Concrete Workflow 1 / Workflow 2 details are ContextView material rather than identity-independent project truth.

For the current `ContextView<ChatGPT, Jason>`, Workflow 1 has Jason trigger Operator when ChatGPT needs local evidence. Workflow 2, once Host production authority is accepted, has ChatGPT/AI reach the same Operator/task surface through DCR-or-successor -> Host. The active view and JasonPC environment profile live under `views/`.

Platform launchers are thin adapters. Windows may use `tools\\qiven.cmd`; POSIX human use may use an appropriate thin launcher. No launcher extension is the project-level contract.

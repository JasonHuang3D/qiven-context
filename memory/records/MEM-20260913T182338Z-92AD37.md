# Cross-platform path identity must use physical canonicalization when repository-root equivalence matters

Brownfield adoption originally compared lexically normalized paths. CI exposed that equivalent physical locations can have different textual identities, including Windows short-name aliases and macOS `/var` versus `/private/var` style aliases.

The fix canonicalized both the requested repository path and Git's reported top-level path with `file(REAL_PATH)` before comparing them. The regression coverage also accepts a physical symlink alias while still rejecting a real Git subdirectory.

The general lesson is not to use lexical absolute normalization as proof of filesystem identity when a security/safety check depends on two paths referring to the same physical root.

# Shell heredocs for file authoring are a defect class

Incidents in the 2026-09-21 v15 session: a heredoc test file truncated
mid-identifier ("trailing.push_b" at 106 lines); an earlier test file
truncated the same way; a failed standard patch whose heredoc terminator
was swallowed while a merge proceeded on the partial content; terminator
collisions between adjacent heredocs in one command. Root cause: bash
heredocs make file content pass through shell parsing (terminators,
quoting, length limits) for zero benefit — the native Write tool writes
atomically with no shell in the path.

Rule: file content is authored through the NATIVE file tools (Write/
Edit/Read) exclusively; bash is for git/cmake/gh/python-execution and
one-line probes. Mixing "write this file" into an execution command to
save one tool call is the exact trade that produced every incident.

Related recurring slip recorded with it: new C++ test files repeatedly
forgot the qiven::u64/usize alias imports (five occurrences this
session) — new test files START with the alias import block.

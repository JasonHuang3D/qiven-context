# Windows spawn/file lessons from the custody rebuild (all live-observed)

Each item was reproduced and fixed inside one batch; the regression
suite pins them. The full normative law lives in qiven-devkit
`docs/engineering/python-standard.md` §2 — this record is the
memory-index-visible summary so cold boots sweep it.

1. **Hand-rolled environment blocks through raw `CreateProcessW` fail
   with `WinError 87`** even when the block looks correctly formed
   (reproduced with minimal blocks and multiple encodings). Use
   `_winapi.CreateProcess(..., env_mapping_dict, ...)` — the stdlib
   path subprocess itself uses.
2. **`STARTUPINFO.hStd*` fields carry HANDLES, not fd numbers.** An fd
   number there silently loses the child's redirected output (empty
   logs with correct exit codes). Convert with
   `msvcrt.get_osfhandle(fd)`.
3. **`bInheritHandles=TRUE` inherits EVERY inheritable handle** —
   including the caller's own stdio pipe. Descendants then keep the
   supervisor's pipe open: a caller waiting on pipe EOF blocks until
   the whole run tree exits (observed: a 1 s supervision budget took
   13.8 s to return). De-inherit your own std fds before spawning
   (`os.set_inheritable(fd, False)`).
4. **`os.replace` collides with concurrent readers on Windows**
   (`PermissionError`, because Python readers cannot request
   `FILE_SHARE_DELETE`). Atomic-rewrite files that other processes poll
   need writer-side retry AND reader-side retry; a live supervising
   process must never crash on a transient write collision (it did:
   the crash killed the custody job and the run with it).
5. **Liveness is wait-based** (`WaitForSingleObject`), never
   `GetExitCodeProcess == STILL_ACTIVE` (259): a genuine exit code 259
   misreports as alive.

Failure fingerprint for future incidents: correct exit codes with
empty logs → item 2; supervision returns late by roughly the child's
runtime → item 3; a supervisor crash with `Access is denied` on a
record path → item 4.

# Broker session identity belongs to Host transport and must not be client-selected on the wire

`BrokerSessionId` is an authority identity owned by the Host transport/dispatcher for one accepted local IPC connection. It is not application data supplied by a remote caller and is therefore absent from the normal Host wire protocol.

The first pre-publication protocol candidate placed `BrokerSessionId` in Acquire, Execute, and Release messages. Exact semantic review rejected that design before the active branch moved: a stale, duplicated, or competing caller could copy the same client-selected value and weaken the same-session ownership checks that `AuthorityState::complete`, release, and disconnect rely on.

The accepted codec checkpoint keeps execution, lease, fencing, sequence, and operation identities in the bounded application protocol while reserving broker-session creation for the future owner-only local transport. The transport/dispatcher must assign a fresh nonzero session identity to each accepted connection and inject it into `AuthorityBroker` calls out-of-band from decoded message fields. Disconnect handling must use that same Host-owned session identity.

This is a representation and authority boundary, not merely a field-layout choice. Client-controlled connection identity would move part of the split-brain safety boundary back across the trust boundary that Host exists to enforce.

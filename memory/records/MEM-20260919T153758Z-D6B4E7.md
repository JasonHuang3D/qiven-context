# Re-entrant mutex through the identity port (2026-09-19)

While landing v3 Phase 1 in `qiven-context-draft`, Debug test runs aborted
mysteriously: exit code 3, no test output beyond the first line, ctest runs
pausing for seconds at a time. Root cause chain, fully captured with cdb:

1. **The defect (draft)**: `QivenContext::AcquireGrant`/`WriteToCognition`
   invoked the identity port while holding the admission mutex; the draft
   verifier re-entered `QivenContext::CanonicalHead()`, re-locking the same
   non-recursive `std::mutex` on the same thread. MSVC Debug throws
   `std::system_error(resource_deadlock_would_occur)` from `_Mutex_base::lock`;
   the draft has no try/catch (by contract) → `std::terminate` → `abort()`.
   MSVC Release silently tolerates the re-lock (recursion counter in
   `mtx_do_lock`), so the same defect passed in Release and crashed in Debug —
   standards-level undefined behavior either way.
2. **The manifestation**: an uncaught C++ exception on MSVC terminates with
   exit code 3 and NO diagnostic anywhere — stdout is lost (abort does not
   flush buffered stdio), stderr is empty. The "Debug Error! abort() has been
   called" modal dialog is the CRT's abort report, NOT a QIVEN_ASSERT: no
   `contract_fail` ran (its first act is a stderr write, and stderr was empty).
   The dialog pauses the process for human input and terminates on EVERY
   button (Ignore does not continue) — the ctest "hangs" were operator click
   latency.
3. **The fixes**: foundation `contract_fail` now terminates via `_Exit(3)` on
   Windows (no modal dialog; stderr + OutputDebugString + DebugBreak-if-
   debugger unchanged) — unattended runs fail closed without human input.
   Draft: ports are called WITH the governance snapshot as context
   (`verify(actor, governanceSource)`); no port signature can re-enter the
   service (DR-013, pit P-42, test `pit.port_never_reenters_service`).

**Diagnostic lessons**: (a) on MSVC, exit 3 + empty stderr + missing buffered
stdout = uncaught exception or terminate, never a logged assertion — go
straight to a debugger stack capture (cdb `-cf` with `sxe e06d7363`); (b) a
modal dialog during any automated run means human latency is being timed, not
machine work; (c) a Debug-only failure with a Release pass is a concurrency or
undefined-behavior smell, not a flake.

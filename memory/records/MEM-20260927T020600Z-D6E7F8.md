# Simulator parity includes the invocation form and the budgets

The simulated gate launched the hook with a hand-rolled argument list
while the SHIPPED kit config (the real caller form) always passes
`--dump-stdin <probe_log>` on SessionStart and PreToolUse, and gives
the hook 15 s / 10 s / 10 s per event. Two consequences:

1. A defective dump path or a slow event would pass the whole simulated
   suite and fail first on the owner machine. The rig must exercise the
   same argument form (asserting the dump lands) and fail any round
   trip over its per-event budget - the slow-client class is bounded
   for tool events, not only hello+event.
2. A client-side property with no observable surface (hello+event on
   ONE connection) is untestable until an observability seam exists at
   the semantic owner: the host now prints one `[open] connection N
   accepted` line per accepted connection, and the rig counts them
   (exactly one per registration). Adding a bounded, flushed
   observability line at the owner of the mechanism is the legitimate
   fix - not a test-only backdoor into the host.

Also measured here: the server accepted an event frame on a fresh
connection without hello, so the one-connection property was NOT
server-enforced - only the counting case discriminates a
split-connection client regression.

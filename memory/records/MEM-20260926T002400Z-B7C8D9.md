# Root-cure governance stance (owner ruling, 2026-09-26 +08:00)

1. **Only `evidence/audits/` and `memory/records/` are iron proof.** For
   the root-cure program (qiven-docs PR #4 and everything landing from
   it), every prior decision — ADRs, architecture documents, state
   entries, project summaries — is a possibly-wrong fallible record.
   Citations of them are consistency notes, never self-justifying
   authority. When a cited decision conflicts with incident evidence or
   memory, evidence wins the review position and the conflict goes to
   owner adjudication.
2. **Host/DCR deletion is executed and adjudicated.** The owner deleted
   the GitHub repositories `JasonHuang3D/qiven-host` and
   `JasonHuang3D/qiven-dcr-win` (observed 2026-09-25T23:33Z: both URLs
   fail to resolve under the authenticated owner account). The history
   is unrecoverable: no archive exists and none will be produced
   (`DELETED_REMOTE + ARCHIVE_FORFEITED`). The ADR-0043 cloud-preservation
   clause requires a dated amendment recording the forfeiture.
3. **The `qiven-process` "seed material" claim is void old-era
   cognition.** Session LLMs of the superseded era self-issued that
   requirement; it was never owner-validated. Runtime already implements
   the host functionality; any future process-layer work starts from
   Runtime's actual code under a fresh decision, never from seed
   recovery.
4. **The declared root defect class** is the old "implement locally
   first, extract when more consumers appear" principle and its
   authoring culture (of which the void seed is the named example).
   PR #4 is the root-cure specification surface: single-owned boundary
   contracts, evidence-bound acceptance, museum discipline for the
   entry-point residue, gates that refuse unsupported claims.
5. **Foundation and Math are retained on actual current value**, per the
   same ruling — retention is earned, not assumed.

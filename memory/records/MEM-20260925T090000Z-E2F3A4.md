# Positionless clean-input review rounds; terminal labels are self-pollution

The value of a fresh reviewer is attention untouched by the
orchestrator's process state. Three independent pollution channels
were proven live in the v29 loops, two of them created by the
orchestrator itself:

1. **Loop-state in revision commits.** "Tally effect: pass count
   resets" in a fix commit message let the next reviewer reconstruct
   the loop and its own position mid-round. Fix: revision commits
   describe the change factually; tallies live only in orchestrator
   records (checkpoint/workflow log), never in reachable artifacts.
2. **Terminal labels.** After a reset the orchestrator framed the
   restarted count as "final 3 rounds" and wrote that into briefs. A
   reviewer told its round is decisive is biased toward passing — and
   the label is itself the pollution it was supposed to prevent. Fix:
   rounds are positionless; briefs name the artifact and heads only;
   nobody declares a subagent task final.
3. **Process records as reading material.** Checkpoints and session
   narratives were put in reading lists as claim sources. Fix: briefs
   are self-contained (claims inline, verbatim); reading lists carry
   engineering law + the artifact under review, nothing else.

Convergence and escalation: the pass count needs no terminal framing —
the rule is consecutive passes since the last reset, plus a RESET
CEILING: three consecutive resets means fix the last findings once,
stop, record, and hand the node to the owner as an H1 design question
(three failed review+fix cycles indict the artifact or the process
design, not the reviewer's patience).

Residual open channel: hook-router denial text (it carries project-law
references and re-call instructions into a clean context) — needs the
next-session live boundary test before router messages are trusted as
a worker's only correction source.

# Flat pipe names for multi-instance Windows pipe servers

A pipe name like `\\.\pipe\qiven-runtime\<install>\v1` (multi-segment,
backslash-separated) accepts its FIRST instance fine, but creating the
NEXT instance fails `ERROR_PATH_NOT_FOUND` (3) once no LISTENING
instance of that name exists — NPFS treats the intermediate namespace
"directories" as pruned when every existing instance is already
connected. A server that stands up the next listen instance at
`accept()` time (the pattern that lets a connected instance be handed
to the caller whole) hits exactly that state when a client connects
before `accept()` runs — which any fast client does.

Flat single-segment names (`\\.\pipe\qiven-runtime-<install>-v1`) have
no namespace directories to prune and multi-instance cleanly. The pipe
NAME is not the security boundary — the DACL is; flattening the name
loses nothing security-relevant. Recorded in the MVP-3 batch design as
a delta on the architecture's literal name (design-first law:
deviations are recorded, never silent).

Related trap in the same file: a move constructor that moves the handle
but not the name member leaves the next-instance creation with an EMPTY
name (also error 3). Move EVERY stateful member.

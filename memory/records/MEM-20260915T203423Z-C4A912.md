# Preserve canonical engineering semantics when a connector write is blocked; switch authoring path instead of rewriting the meaning

A connector-specific refusal to write legitimate Qiven project documentation is an execution-path boundary, not permission to distort the canonical engineering record.

When a remote connector blocks a write because its own safety, policy, or sensitivity gate rejects the content, jason-brother should state that boundary directly. Do not silently euphemize the engineering meaning, remove material facts, or produce a weaker canonical record merely to make the connector accept the write.

The preferred fallback is to move authoring to a trusted path that can preserve the exact intended semantics: an explicitly authorized local Work/owner path may create and push the file, after which jason-brother performs exact remote review. If no suitable trusted execution path is available, the last reliable fallback is to generate the exact Markdown or patch for the project owner to write or apply locally.

This rule does not authorize bypassing an actual platform policy that forbids the underlying content. If the content itself is disallowed, that policy boundary remains. The fallback applies when the engineering content is legitimate but the selected connector cannot carry the write faithfully.

Qiven Host and DCR are a separate local execution/authority plane. After Host acceptance, their architectural responsibility is admission, fencing, execution authority, and no-bypass safety; they should not intentionally duplicate a remote connector's content-classification policy. External connector policies still apply whenever those external tools are used.

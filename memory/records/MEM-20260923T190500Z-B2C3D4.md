# Non-TTY git HTTPS dies on obsolete GCM helper config; exec was innocent

Root cause (verified 2026-09-23/24): the user-global gitconfig carried the
renamed-away `credential.helper = manager-core`; in any non-TTY git process
GCM's dialog attempt auto-cancels, the obsolete helper name fails, and no
prompt fallback exists - so git HTTPS auth fails identically in exec children
AND raw session shells. SSH remotes (qiven-devkit, qiven-runtime) were never
affected; gh API operations use their own keyring auth.

Fix applied (one-line revertible): `credential.helper = manager` globally,
plus `credential.https://github.com.helper = !gh auth git-credential` scoped
to github.com (empty value first resets the list for that URL). Verified by
raw push success.

Law: do not blame the custody layer for environment failures its logs
honestly report - the exec log named the credential chain precisely. The
hook router's git-network class is suspended (devkit 3065018 / main 71f1c62,
`GIT_NETWORK_ROUTING_ENABLED = False`) until the owner reinstates the
measured judgment; probe logic and tests are intact under the flag.

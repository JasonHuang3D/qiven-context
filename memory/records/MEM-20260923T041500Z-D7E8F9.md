# SQLite keyword identifiers compile in DDL and fail in DML

The journal schema keeps a `transaction` column (cpp-design 7.3 naming).
SQLite ACCEPTS the bare keyword inside `CREATE TABLE` but rejects it in
`INSERT INTO t(... transaction ...)` and every `WHERE transaction ...` —
so the defect survives schema creation and fires on the first DML,
surfacing as an "open failed" error layers away from its statement.

Rules adopted in the MVP-1 batch:

1. Reserved-word columns are quoted (`\"transaction\"`) in DML and DDL
   alike, including qualified (`d.\"transaction\"`) and subquery forms.
2. The schema-conformance test drives every table family through real
   command calls, so a DDL-only-accepted keyword cannot reach production.
3. When a SQL error surfaces far from its statement, check the failing
   statement's identifiers against the SQLite keyword list before
   suspecting the wrapper layer.

# Current Qiven product roadmap starts with DCR Windows transport before CAD

The current long-term product sequence is:

1. Qiven DCR Windows / execution transport — first stabilize the Windows transport plane with a native supervisor, bounded logging/lifecycle/health and minimal Win32 UI; native wire transport is a later phase after protocol reconnaissance;
2. CAD / floor-plan to semantic 3D;
3. industrial-gas enterprise management/operating system;
4. robotics/simulation, initially in the class of a MuJoCo-like simulator but intended to grow beyond a clone;
5. deeper Qiven-native physics when product and simulator requirements justify owning more of the physics stack.

The DCR Windows insertion is intentionally bounded. It exists because transport reliability and turn compression affect every later product line; it does not authorize indefinite infrastructure work. The first transport milestone has an explicit completion boundary in `projects/dcr-win/README.md`, after which priority returns to CAD.

## Supersession

This roadmap ceased to be current when the split-brain incident required ADR-0026 Host authority work and ADR-0027 production-integration gating before mutating DCR could resume. Current planning belongs in `state/roadmap.yaml`; historical sequence remains here for provenance.

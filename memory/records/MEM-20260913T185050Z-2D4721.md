# Natural-language YAML fields require safe serialization or explicit quoting

Batch 001 checkpoint validation exposed a concrete failure mode: human-readable provenance containing YAML-significant text such as `: ` can make a canonical record syntactically invalid when inserted as an unquoted plain scalar.

The durable rule is therefore stronger than "be careful with YAML": automated generation should use a YAML serializer, and manual canonical edits should quote or block-scalar natural-language values whenever their syntax could be ambiguous. Repository validation is part of the write path, not an optional afterthought.

A visual review of a Markdown file is not evidence that its YAML front matter parses correctly.

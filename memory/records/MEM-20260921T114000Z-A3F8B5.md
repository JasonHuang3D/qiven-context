# Operator exec: detached supervised execution for LLM-invoked commands

The timeout/heartbeat contract bounded the wait but could not keep the
real command alive when the invoker's shell died, and a blocking proxy
would die with it. `qiven exec` dissolves the class:

- `exec start --timeout S -- CMD...`: child DETACHED in its own process
  group (breakaway best-effort with honest fallback), durable run log
  under `.generated-temp/operator/exec/`, operator heartbeats while
  supervising, returns exit 124 still-running at its own ceiling — the
  child CONTINUES.
- `exec status/stop/list`: cheap re-attach (runfile + liveness + log
  tail), process-tree kill, inventory.
- Unobserved exits report `indeterminate` — never a guessed exit code.
- Rolled to managed repos via devkit sync (template drift repaired in the
  same PR; the template had been stuck in the pre-subcommand era).

Amendment 2026-09-21 (owner direction, option A installed): a ZCode
PreToolUse hook (matcher Bash; command inspected inside the hook) now
denies long-class raw commands with the exec replacement pattern as the
reason. Script: qiven-devkit/tools/hook_exec_router.py (devkit PR #14,
merge 98bab5a); workspace config: <workspace-root>/.zcode/config.json with
hooks.enabled true. Standalone verification passed all four command
classes; in-session live firing was NOT observed (workspace config most
likely loads at session start, not hot) - activation to be confirmed at
the next session start or in client settings. Silent command rewriting is
NOT a documented ZCode hook capability (allow/ask/deny + reason +
additionalContext only) and was judged undesirable anyway; the
token-optimal path is native exec usage via the pointers, with the hook
as backstop.

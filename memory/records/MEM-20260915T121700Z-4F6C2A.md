# Recover DCR transport loss by reconciling local state before replaying work

A DCR/network interruption does not prove that already-dispatched local work stopped or that a mutation failed. Chat/UI transport state, DCR relay state, local process state, filesystem state, and Git state are separate evidence domains.

After transport restoration, prove liveness with `ping` or a minimal bounded operation, inspect any surviving sessions/processes when relevant, and reconcile the target filesystem/Git state before retrying. Resume from the last proven local boundary and replay only work proven not to have completed.

The 2026-09-15 incident preserved a complete header and a partially written source file across a Clash upstream outage; fresh DCR recovery correctly resumed from those files rather than restarting the implementation sequence.

Human CMD remains the fallback when DCR cannot be restored promptly.

# Verification PASS evidence is scoped to the invocation environment

A tool-built H1 kit (ADR-0049) is not self-contained merely because its
builder verified it: the verification run itself carries environment
assumptions. In the 2026-09-24 incident, the session-side PASS was
produced from the repository working directory, where the CWD-derived
default profile happened to exist; the owner's double-click ran from the
kit folder, where nothing provided it. Extend the kit law: (1) a kit's
pre-flight must reproduce the OWNER-LIVE invocation environment (double
click working directory, launcher-relative paths, packaged file set), or
pin resolution explicitly (fixed cwd / absolute --profile) so behavior
does not depend on where the entrypoint is invoked from; (2) any
CWD-dependent default in an owner-facing executable is a defect of the
same class as an ambient dependency (ADR-0052 WG-3 in spirit), even when
no revision selection is involved; (3) expected cold-path outcomes must
not be labeled [FAIL] - mislabeled severity sent the owner a false
failure signal that cost a trial.

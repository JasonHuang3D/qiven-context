# CREATE_NO_WINDOW, not DETACHED_PROCESS, for detached console children

`DETACHED_PROCESS` gives the child NO console. Any descendant that needs
one (cmd.exe batch chains, vcvars, build tools) then allocates a NEW
console — VISIBLE: popup windows flash on screen and their output goes
to the popup instead of the redirected handles (empty-log symptom), and
console-DLL initialization can fail outright (child exit `0xC0000142`).
`CREATE_NO_WINDOW` gives the child a HIDDEN console: every console in
the tree is invisible, stdio stays on the redirected handles, console
init succeeds. Pair it with:

- `CREATE_NEW_PROCESS_GROUP` (+ `CREATE_BREAKAWAY_FROM_JOB` with a
  no-breakaway retry) for the survival properties;
- explicit `cmd.exe /d /c call <absolute path>` for `.cmd`/`.bat`
  targets (CreateProcess's implicit batch dispatch is undocumented;
  `/d` skips AutoRun registry scripts);
- argv[0] path resolution against the child's intended cwd (CreateProcess
  resolves the application against the CALLER's directories, so a
  plausible relative path can still fail with WinError 2);
- recording the actual spawned argv (`spawn_argv`) in run records — the
  0xC0000142-class postmortems need it.

Symptom fingerprint for future incidents: empty exec logs + nonzero
fast exits + (owner-visible) console popups = a detached-process spawn
somewhere in the chain.

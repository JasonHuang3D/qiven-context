# ZCode harness PoC scars (2026-09-25/26, owner-approved feasibility PoC)

Verified traps when patching/building/driving ZCode Desktop or CLI on
the owner machine; each cost a debugging round and all are avoidable:

1. **Env values eat backslash escapes in transit** - the session tool
  channel re-interprets `\\` as `\`, silently corrupting JSON env
  values (`ZCODE_AGENT_SERVER_ARGS_JSON` failed as "Bad escaped
  character"). Use forward slashes in every path inside env values.
  Same defect class as the heredoc/escape-eating law.
2. **Host-prepared env inheritance** - shells and children of a
  running Desktop inherit `ZCODE_DATA_BASE_DIR` and provider-config
  env vars pointing at the real data root; they silently override
  scratch isolation. Pin `ZCODE_PERSONAL_PROVIDER_CONFIG_FILE` and
  `ZCODE_BUILTIN_PROVIDER_CONFIG_FILE` explicitly (builtin must point
  at the repo's shipped builtin manifest, not a personal config).
3. **Packaged-Desktop isolation stack** - a second instance sharing
  app name/userData hits the single-instance lock and just activates
  the running app (env goes nowhere): isolate with
  `ZCODE_DESKTOP_APPLICATION_NAME` + `ZCODE_DESKTOP_USER_DATA_DIR`;
  the business root is then still read from
  `<homedir>/.zcode/v2/setting.json` (`dataBaseDir`), overriding
  `ZCODE_DATA_BASE_DIR` - point `USERPROFILE`/`HOME` at a scratch
  profile (pre-created with `AppData/Roaming`, else ARMS RUM dies at
  module init).
4. **Failed startup is not process exit** - a launched instance that
  logs `app_startup_failed` may keep running headless with live
  helper children; its background task stays "running" truthfully and
  no completion notification arrives. The UI running-state is the
  fact; sweep by CommandLine match before assuming death.
5. **Background task ids are `exec_<8hex>-<uuid>`** - TaskStop with a
  truncated prefix returns "No task found" while the task runs
  (misread once as a tooling defect; it was operator error). Always
  copy the full id. TaskStop may still leave sh.exe/cmd wrapper
  stragglers - sweep and `taskkill /T /F` before declaring clean.
6. **The working Desktop-chain recipe is `pnpm dev:desktop:test`** -
  it rebuilds the patched agent and starts an isolated "ZCode Dev"
  app that spawns the patched agent; one GUI message produced the
  full logical -> final-permit -> wire evidence chain. The isolated
  PACKAGED instance instead exits cleanly before agent spawn
  (undiagnosed; only matters for future packaged-profile trials).
7. **Isolated trials must never log in a real account** - the fresh
  app shows official onboarding; a real SMS login's `zcode://`
  callback can be captured by the running official instance and the
  isolated app errors with `userId: null` (no token residue in
  scratch - verified). Use the loopback mock provider for every
  model call.

Cost model measured: portable Node+pnpm setup minutes; monorepo
install 2m28s; narrow agent build 64s; the PoC was executed with
worker subagents doing code/build/test while the main session only
decided and orchestrated.

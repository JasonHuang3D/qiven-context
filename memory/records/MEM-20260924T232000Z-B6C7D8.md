# Audit the workspace, not the inherited list; publish pin ripples bottom-up

Two coupled lessons from the v25 full-workspace coverage batch:

1. An obligation's inventory is a claim, not evidence. The sibling
   rollout obligation (written under incident pressure in v20) named
   four repositories; the real v1-carrier set was three, overlapping
   by only two — one listed repo pair had nothing to roll, and one
   actual carrier (context-draft, with a CUSTOMIZED operator.json) was
   invisible to every prior record. Before executing (or closing) any
   workspace-wide obligation, enumerate the tree live (operator
   snapshots: `.qiven/repo.json` template_version + custody markers in
   `tools/qiven_operator.py`; shim consumers: `devkit_pin`) and treat
   divergence from the record as a finding to correct in the same
   batch.

2. Cross-repo SHA pins turn a "tooling-only" sync into a bottom-up
   publication wave: consumers verify pins at configure time, so every
   upstream merge fails every downstream gate until re-pinned. Publish
   lowest layer first (foundation), merge, then re-pin direct consumers
   (math, draft) against the published merge heads, then the next tier
   (runtime pins foundation AND draft). Budget for the ripple instead
   of discovering it as serial gate failures.

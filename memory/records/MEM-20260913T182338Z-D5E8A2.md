# Devkit lifecycle operations are conflict-atomic by preflight but not crash-consistent filesystem transactions

Adoption and sync deliberately compute conflicts before normal mutation and abort without changing repository files when a known conflict exists. That is a strong logical all-or-nothing guarantee for validation/conflict detection.

The implementation then performs a sequence of filesystem copies/deletes and metadata writes. It does not implement a journaling or rollback transaction that guarantees recovery from process termination, power loss, or an unexpected filesystem error after mutation begins.

This limitation is accepted for the current Devkit scale. It must not be described as full crash-atomic transactionality.

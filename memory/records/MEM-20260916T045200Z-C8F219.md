# Host-owned broker session identity outranks copied client execution identity for competing Acquire detection

`ExecutionId` is caller-controlled application identity. It may be duplicated by two stale, forked, or otherwise competing callers and therefore cannot prove that two Acquire attempts originate from the same Host authority.

`BrokerSessionId` is established by Host transport for an accepted local connection. While authority is already `Leased`, a different Host-owned session is competing authority even if it presents the exact same `ExecutionId`. `AuthorityState::acquire` must enter `Quarantined` and return `concurrent_execution`; the broker must persist that stronger phase before returning the rejected Acquire.

A repeated Acquire from the same Host session and same execution is different: it is rejected as `concurrent_execution` but does not alone prove split-brain and therefore remains `Leased`. Missing stored session or execution identity in a state that claims to be `Leased` also fails closed to `Quarantined`.

Exact Windows regression restarts `AuthorityBroker` after the different-session/same-execution rejected Acquire and proves `Quarantined` survives replacement. This closes the gap where copying client identity could otherwise weaken Host-owned connection fencing.

# qiven-toolchain-win currently pins CMake and clang-format as executable build tools

At the verified Genesis pin `a79825031e838d80354d31489c87327dd6adbfb7`, `toolchain.json` declares exactly two pinned tools:

- clang-format `19.1.7`, sourced from `llvm-project/llvmorg-19.1.7`;
- CMake `4.4.3`, sourced from `Kitware/CMake/v4.4.3`.

This repository answers the executable-tool question for those declared tools. It does not, by the manifest alone, establish pinned ownership of MSVC, the Windows SDK, CUDA, Python, or every other host dependency. Do not infer broader toolchain ownership merely because the repository is named `qiven-toolchain-win`.

The responsibility boundary remains the one already captured by ADR-0010: toolchain owns pinned executable build tools; Devkit owns repository conventions and lifecycle workflows.

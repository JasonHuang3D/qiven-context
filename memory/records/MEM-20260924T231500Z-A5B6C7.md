# Proven background-path facts (and the one that was wrong)

Fresh-session probes (v25) confirmed the ADR-0051 mechanics live:
notification-once (P1), full-tree TaskStop kill (P2), and the natural
deny→re-call flow (P5, observed for both gate-class and sweep-class).

The v24 mitigation line claiming "the Bash timeout parameter bounds
calls" was WRONG for the background path: timeout=6000 did not kill a
45s background task (P3). A background re-call is bounded only by its
command's own duration, TaskStop, and (unproven until the P4 straggler
check) session end. Consequences already landed: the ADR's residual-R1
wording is corrected, and background re-calls must be
inherently-terminating commands — never rely on the timeout parameter
for a backgrounded call.

Session-end survival (P4) remains the open fact; a bounded straggler
probe is left at v25 close for the next session to observe.

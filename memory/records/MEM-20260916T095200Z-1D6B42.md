# Human-facing Windows batch entrypoints must preserve terminal outcome on direct launch

A script intended for direct human execution must treat terminal lifetime as part of its interface. A double-clicked `.cmd`/`.bat` may own the transient CMD process, so a terminal `exit /b` can close the only place where success or failure was printed.

Default human mode therefore converges all terminal paths on visible success/failure handlers, prints stable final state, pauses before returning, and only then exits with the truthful code. Non-pausing behavior requires an explicit automation mode such as `--no-pause`. Multi-stage human validation belongs in a repository/local orchestration script rather than a fragile long shell chain.

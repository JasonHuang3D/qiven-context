# Merged-contract types are unproven until first instantiation

MVP-0 landed `IRuntimeJournalPort::append` returning `qiven::Result<void>`
— a declaration never instantiated anywhere (declarations do not require
complete return types; no override or call existed). A 30-second compile
probe before implementation proved the type ill-formed: the primary
template's success channel is the implicit `Result(T)` constructor, the
default constructor is private to `fail()`, and an anonymous union
holding the non-trivial `Error` deletes even that.

Rules adopted:

1. When a batch is the FIRST to instantiate a merged contract surface (a
   new generic parameterization, a first override, a first call), compile-
   probe that surface alone before building on it — minutes of probe
   versus a broken build under a finished implementation.
2. The fix belongs in the semantic owner (foundation PR #17:
   `Result<void>` partial specialization with an `ok()` success channel
   and the primary template's named-union storage), not a consumer-local
   workaround; one concrete downstream requirement is sufficient
   evidence to fix the lower layer (philosophy section 2).
3. Consumers re-pin explicitly (runtime 424a9a8 -> 209874a); other
   consumers' exact-SHA pins remain valid — a foundation change does not
   cascade until each consumer moves.
